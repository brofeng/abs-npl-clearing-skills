## ★★★ 定源铁律（第一优先，先于复刻铁律）

**评级报告永远只认「中债资信」那一份。** 因为**发行规模分层**与**回收预测**都以它为准，
这两个是全报告的分母与对标基准，换源等于换了一套报告。

| 源 | 定位 | 取什么 |
|---|---|---|
| **中债资信评级报告** | ★★★ **唯一权威**（扫描件，**必须 OCR**） | 发行规模分层（优先/次级/证券占比/信用等级/回收占比）、预计回收金额与回收率、逐期预测回收现金流 |
| **发行说明书** | ★★ 合同与明细唯一源 | 分配顺序 (a)–(n)、17% 上限、清仓回购、超额奖励、职业分布、城市级地区分布、资产池描述统计、证券要素 |
| **受托机构报告 1–5 期** | ★★★ 存续期唯一源 | 逐期回收/分配/分档兑付/信托账户余额 |
| 清算审计 + 专项复核 | ★★★ 终局唯一源 | 剩余财产、持有人权益、清算净收益、审计意见 |
| 中债国债收益率曲线 | 市场数据 | 无风险利率 Rf（XNPV 折现） |
| **联合资信 / 其他评级** | **○ 仅供参考** | **不作取数来源，不进报告**。可交叉校验，数值一律不采用 |

> ⚠ **三组禁用数值**（来自联合资信，与本技能口径冲突，永不出现在报告里）：
> 预计回收 `74,762.74 万元`、回收率 `18.29%`、加权平均逾期 `4.23 月`。
> 本技能采用：`74,726.80 万元` / `18.28%`（中债资信）、`4.73 月`（发行说明书）。

> 字段级取源表、口径冲突表、说明书定点查法（省 5–8 倍时间）→ **`references/18-数据取源优先级.md`**

## ★★★ 复刻铁律（第二优先，违反必失败）

> 实测结论：本技能 `scripts/single/` 构建的单项目报告与基线 **SHA256 字节级一致**
> （`deeef1e06070013a…`，205,040 B），且**与目录、机器、盘符无关**（已实测跨目录复现一致）。
> **复刻失败 = 没用这套代码 / 漏跑模块 / 自己重写 / 没验证**，不是代码问题。

### 铁律 1：跑 `scripts/single/`，不要重写模块

```bash
python scripts/single/build_single.py --out <输出目录>    # 唯一构建入口
python scripts/single/repro_gate.py --html <产物>         # 一键门禁，必须 EXIT=0
```

26 万字符级 CSS/JS 里藏着大量未文档化的细节（0.5px 间距、`scope_css` 三个坑、标签配平、
重绘时机、折行宽度）。**手工重写必然漂移**，且用户一眼能看出。

### 铁律 2：不要改 `--window-size`

必须 `1600,1400`。响应式断点（1180 / 900 / 767 / 560）会改栅格列数、卡片高度、字号
——**换尺寸就不是那张图**。该常量写死在脚本里，不要传参覆盖。

### 铁律 3：交付前必须 `repro_gate.py` EXIT=0

不跑 = 不知道对不对。跳过验证视为未完成。

### 铁律 4：不要为了让门禁通过而改基线

基线（`assets/single/golden/`）是用户已验收的样子。改基线 = 宣布新样子才对。
**只有用户明确要求改版时**才 `--rebless`，且须在 `README.md` 写明原因。

### 铁律 5：不要手改输出换行

`build_single.py` 用 `newline=""` 写入（不转换）。改成默认 newline 会多 1,483 字节，G1 立即失败。

### 三级门禁

| 级 | 手段 | 强度 | 耗时 |
|---|---|---|---|
| **G1** | 产物 SHA256 vs `golden/report.sha256` | 字节级（最强） | 1 秒 |
| **G2** | 逐节「版式+文案」指纹 vs `golden/spec.json`（93 项） | 语义级 | ~40 秒 |
| **G3** | 语义断言 **137–144 项**（独立复算 + 跨单合理性 + 禁用词 + 渲染后内容，条数因单而异是设计预期） | 数值级 | ~40 秒 |

> 完整 DoD、失败定位表、Agent 交接清单 → **`references/17-复刻验收DoD_v2.md`**
> 3.0 逐条门禁清单（新增 25 条各抓什么错、容差依据）→ **`references/20-跨单门禁清单v3.md`**

### ★ 3.0 的门禁分两种结果，必须分清

| 状态 | 含义 | 退出码 |
|---|---|---|
| **FAIL** | 数据真有问题 | 1 |
| **SKIP** | 输入字段缺失，判不了（**不等于通过**） | 0 |
| **EXIT=2** | 输入契约不满足（取数漏项），断言没跑 | 2 |

第 2、3 种不能当 PASS 处理，也不能当 FAIL 处理。字段契约见
**`references/19-取数契约与字段字典.md`**。

### ★ 3.0 的 rebless 保护（最容易被忽略的一条）

```bash
python repro_gate.py --rebless                      # 先跑 G3，全过才允许重设基线
python repro_gate.py --rebless --force --why "原因"  # 强制跳过（须用户明确同意）
```

2.0 的 `--rebless` 直接把当前产物定为黄金。**若产物有错，错误就被固化成「正确」**，
之后 G1/G2 永远通过，门禁等于废掉。3.0 强制先过 G3，并把旧基线归档到 `golden/history.tsv`。

## 工作流（单项目，9 步）

0. **校验输入** —— `build_single.py --check`（字段齐备 + 指纹一致）
1. **读口径** —— `references/02` + `references/16` 第十二节（唯一口径表）
2. **读版式** —— `references/15`（8 节结构指纹与渲染后全文）
3. **先跑基线** —— `build_single.py` + `repro_gate.py`，**G1 必须通过**。
   不通过就先解决环境（Edge / 字体 / 换行），**不要往下走**
4. **按需求改造** —— 只改 `build_single.py` 里对应的 `secN()` 函数，不碰 CSS
5. **视觉打磨** —— 读 `references/07`，用母版令牌，不自创配色
6. **断言验收** —— `verify_single.py`，FAIL 必须为 0
7. **★ 复刻验收** —— `repro_gate.py`，EXIT=0 才可交付
8. **出图 + 留痕** —— `shots_single.py` + `README_v<N>.md`（改了什么/修了什么/遗留什么）
9. **版本重命名** —— v1/v2/v3…，不覆盖

## 每次迭代必做

1. **核实用户点评**（约 20% 是旧版信息或误读，不要照单全收）
2. 先跑数据验证，再动手
3. 改完先跑 `repro_gate.py --only g1` 看是否只在预期处变化
4. 组装 → 断言 → 出图 → README
5. **重命名交付物**，不覆盖
6. **留痕**：`README_v<N>.md` 写清改了什么、核实了哪些点评、遗留什么
7. **★ 贴出门禁结果**（G1/G2/G3 状态 + 产物 SHA256）

## 三条最贵的经验

1. **数据门控先于一切**：字段不存在（预测 XIRR / 发行利差 / 约定资金成本率）就绝不画；推算值不当披露值。
2. **断言要验证用户看到的东西**：客户端改写后源文件仍含原文 → 必须查渲染后 DOM；**断言本身的错误率约 40%**。
3. **口径有争议的指标宁可不做**：次级档固定资金成本倒算存在口径分歧，只展示披露值最稳。

## 常见误区

| 误区 | 正解 |
|---|---|
| 「我看懂逻辑了，自己写一个一样的」 | 必须跑 `build_single.py`，26 万字符 CSS 里全是未文档化细节 |
| 照单全收用户点评 | 先逐条查数据核实；约 20% 是旧版信息 |
| 用源文件做「去术语」断言 | 查**渲染后 DOM** |
| 只查同图单位词一致 | 整图差 1 万倍时单位词仍自洽 → **跨图比量级** |
| 比例指标分子分母单位不同 | 万元 ÷ 元 = 差 1 万倍；必须断言「占比合计 = 100%」 |
| 拿资产池余额当账户期初 | 账户勾稽只能用受托报告 P4「信托账户核算概况」 |
| 用百分比反推达成率 | 用金额 ÷ 金额（18.28% 反推差 2bp） |
| 实际累计挂在预测收款期末日 | 中债预测期末日不是支付日，会造出不存在的日期 |
| 披露概览 N ≠ a+b+c | 列了「缺失材料」就必须计入 c |
| 清仓回购价款混入自然回收 | 须单列「自然清收回收率」 |
| 用户说「可以考虑 X」当成全量替换 | 是建议，先判断范围 |
| 为了通过而放宽断言 | 改断言要有实测数据支撑 |
