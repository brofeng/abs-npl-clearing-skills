```python

# 分类标签：1=总览 2=档案 3=横向对照 4=图表/数据 5=单位 6=瀑布 7=交互 8=工程
```

## 四、必做的「反向验证」

新加断言后，**先确认它能抓住已知 bug**：

```python
# 例：确认量级断言能抓住 P0
# 人为把 p0 圆环中心改成「11.92 万」→ 断言应 FAIL
# 若仍 PASS，说明断言写错了
```

本项目靠这一步发现过 3 次「断言形同虚设」。

## 五、断言失败时的定性流程

```
断言 FAIL
  ├── 是实现问题？→ 给 agent 精准返工（带实测证据）
  └── 是断言问题？
        ├── 判据不准确（如拿 poolTotal 去比其他指标）→ 改判据
        ├── 测量时机错（视图未激活/模块未渲染完）→ 改时机
        ├── 选择器猜错 → 先 dump 真实类名
        └── falsy 陷阱（0 or 99）→ 用 is not None
```

**判断标准**：这个断言 FAIL，用户会不会看到错误的东西？
- 会 → 改实现
- 不会 → 改断言（并用实测数据说明为什么不影响用户）
