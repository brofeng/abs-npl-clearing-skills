# 01 · 数据契约与字段边界

> 本技能的核心资产：**知道每个字段有什么、缺什么、能不能用**。
> 原则：**不得臆造、不得补 0、不得把推算值当披露值。**

## 一、数据源分层

| 层 | 路径 | 用途 |
|---|---|---|
| **原始 payload** | `<项目>\_校验件\payload.json` | 唯一权威源。含 `periods / alloc / alloc2 / tranche / xirr / forecast / dist / disclosures` |
| **适配层** | `设计资产\payload_28.json` | `{PROF, ORDER, FL, GROUPS}`，前端用。**是从原始 payload 派生的** |
| **原报告** | `<项目>_报告.html` | 服务端已渲染 28 单 × 8 节 + SVG，作为 BASE |
| **发行说明书** | `发行说明书_<单名>_<年>.pdf` | 回源核对的唯一依据（页码要记） |

## 二、原始 payload 每单的顶层键

```
key bank dir setup_date liquidation_date buyback n_periods
pool calibers forecast_leak dist uncategorized periods acc_checks acc_all_balanced
tranche forecast recon alloc alloc_label_display xirr variety supply alloc2 disclosures
```

### 关键子结构

**`periods[]`** — 逐期账户
```json
{"period":"第1期","begin_date":"2023-12-07","end_date":"2024-02-26","pay_date":"2024-02-26",
 "in":122367432.1,"out":120540366.7,"begin":0.0,"end":1827065.4,
 "outflow":[{"label":"税费支出","amount":191730.6}, ...]}
```
- `outflow` 是**逐期逐科目金额** → 逐期 100% 堆叠条 / 每期固定资金成本都从这里取
- 恒等式：`begin + in − out = end`（28/28 成立时才能称「账户配平」）

**`tranche`**
```json
{"tranches":["优先档","次级档"],
 "period_principal":[[优先逐期],[次级逐期]],
 "period_interest":[[优先逐期],[次级逐期]]}
```
- `null` 表示该期无数据（不是 0）

**`xirr`**
```json
{"computable":true,"invest_date":"...","rows":[{"seq":"0 投入","date":"...","t":0,"cf_sen":-1.7e8,...}],
 "senior":{"issue":1.7e8,"coupon_raw":"3.08%","coupon":0.0308,"xirr":0.0311,"rate":0.0308,"xnpv":...,"cum_cf":...},
 "sub":{"issue":5.7e7,"xirr":0.2791,"xnpv_ref":...,
        "ref_rate":0.0308,"ref_rate_src":"优先档票面",   ← ⚠ 这是优先档票面，不是次级约定率
        "cum_cf":...,"multiple":1.3813,"has_sub_label":false}}
```

**`alloc` / `alloc2`**
- `alloc.cum`：累计科目额（含**未拆分额**、`处置费用`）
- `alloc2.rows`：分组结构 `{role:group/leaf/subtotal/total/split, label, cum, tier, item}`
  - `tier ∈ {senior, sub}` 的 leaf = **分档兑付表口径**（权威）
  - `split` 含 `固定资金成本 / 超额收益 / 未拆分额`

**`dist`** — 10 类分布（前端 `__V2.DIST`）
```
balance grade guarantee overdue age income credit occupation region recrate
每桶: {label, bal, bal_pct, n, n_pct, rec, rec_pct, avg}
```
- ⚠ `bal` 单位 **万元**；每桶同时有 `bal` 与 `n`，**绘图必须显式声明按哪个口径**

| `xirrSen` / `xirrSub` | **28/28** | |

| `subExcess`（次级超额收益） | **28/28** | |
| `subMultiple`（回报倍数） | **28/28** | |

## 四、派生口径（自己算，但必须写明定义）

| 派生量 | 定义 |
|---|---|
| 处置费率 | `disposeFee / recovered` |
| 证券化率 | `issue / poolTotal` |
| 回收率 | `recovered / poolTotal` |
| 达成率 | `recRate / expRecRate`（`vsForecast` 不一致时按此重算） |
| diff_pp | **实际回收率 − 预测回收率**（统一符号，不得正负相反） |
| 资产本金 | `poolPrincipal`（**不是** `issue`） |
| 发行年份 | 项目 key 正则 `(20\d{2})\s*年` |

## 五、已知数据缺陷（必须在报告里披露，不得静默）

1. **`pool_intfee` 口径不一致**：中誉至诚2024年第五期只存了入池**费用** 283,335,660.03，缺入池**利息** 157,533,519.48。已用发行说明书 p121 证伪（本息费 2,237,824,631.87 = 本金 + 利息 + 费用）
2. **`alloc` 与 `periods` 口径差**：7 单差 1%–4.44%，分配表 vs 逐期账户对不到分毫 → 瀑布用「账面结余」如实显示，**不强行调平**
3. **`subFixed` 推算值陷阱**：20 单的 `subFixed` 是推算，只有 8 单是分配明细真实单列
4. **T 日「处置费用」重复计入**：6 单（建鑫2022一/六期、橙益2024八/十一/十二期、橙益2025十二期）在分配表 `out_total` 里重复计了处置费用 → 检测式 `|(rec − out_total) + 处置费用| < max(1, rec×0.5%)`
5. **地区分布最多 342 类**、职业 37 类 → 必须 TopN
