# 22 · 零上下文复现手册（给其他智能体）

> 你手上没有做过这个项目的记忆。这份手册假设你对"清算期不良ABS"零了解，
> 照着做就能从数据产出报告并过门禁。**每一步都给了预期输出和失败处理**——
> 如果你的结果和预期不一致，别继续往下走，先解决差异。

## 〇、先搞清楚这个技能能做什么、不能做什么

技能分两段，边界很清楚：

```
【L2 上游取数】PDF 披露文件 ──→ payload.json + metrics.json
                 ↑ 这一段技能只给「方法 + 字段契约」，不提供下载/OCR/解析脚本
                   （各项目源文件结构不同，无法通用。方法见 references/00、08、18）

【L1 本技能】  payload.json + metrics.json ──→ 单文件 HTML 报告 ──→ 三级门禁
                 ↑ 这一段完全确定性、字节级可复刻，有黄金基线
```

**如果你只是想复现报告版式与门禁**：只需要 `payload.json` + `metrics.json`
（技能自带惠元 2021 年第三期的一份，在 `assets/single/`），直接跳到第三节。

**如果你要从 PDF 开始**：先读 `references/00-从零到交付全流程.md` 与
`references/18-数据取源优先级.md`，自备取数脚本，产出符合 `references/19-取数契约与字段字典.md`
的 payload，再进第三节。

## 二、目录约定

```
<项目根>/
├─ 01_下载文档/        中债官网原始 PDF（含 _下载清单.json）
├─ 02_提取数据/
│   ├─ 文本/           可直取文本的 PDF 转出的 .txt
│   ├─ OCR/            扫描件的 OCR 结果 *.ocr.txt
│   ├─ payload.json    ★ 结构化数据（本技能唯一输入）
│   └─ metrics.json    ★ 派生指标
├─ 03_报告产出/
│   ├─ <项目名>_不良ABS穿透分析_v1.html
│   └─ _assert_single.json    断言明细（自动生成）
└─ 产线/
    ├─ assets/single/
    │   ├─ payload.json  metrics.json      输入副本
    │   └─ golden/report.sha256  spec.json 黄金基线
    └─ scripts/single/                    本技能脚本
```

**关键**：`repro_gate.py` 用「脚本所在目录往上两层」当技能根，
所以它读的是 `<项目根>/产线/assets/single/`，不是技能安装目录。
把脚本复制到 `产线/scripts/single/` 后，它自动指向 `产线/assets/single/`。

## 三、复现一份报告（L1，确定性）

### 步骤 1 · 准备输入

把该单的 `payload.json` 与 `metrics.json` 放进 `产线/assets/single/`：

```bash
copy "E:\<项目>\02_提取数据\payload.json" "E:\<项目>\产线\assets\single\"
copy "E:\<项目>\02_提取数据\metrics.json" "E:\<项目>\产线\assets\single\"
```

`payload.meta.file_name` 决定产物文件名，必须与预期一致。

### 步骤 2 · 体检

```bash
cd /d "E:\<项目>\产线\scripts\single"
python repro_gate.py --preflight
```

字段契约必须是 ✅。若报「缺 N 项」，说明取数器漏了必需字段 → 回到上游补，
**不要在 payload 里手工填数**（那等于让断言自证）。

### 步骤 3 · 构建

```bash
python repro_gate.py --out "E:\<项目>\03_报告产出"
```

这一条会：构建 → G1 → G2 → G3，全通过才 EXIT=0。

首次构建若 G1 报「基线缺失」是正常的——还没建基线。此时：

```bash
# 先确认产物是否真的对（看 G2/G3 是否全过）
python repro_gate.py --html "E:\<项目>\03_报告产出\<产物>.html" --only g3
# G3 全过后才允许建基线
python repro_gate.py --rebless --html "E:\<项目>\03_报告产出\<产物>.html"
```

⚠ **不要跳过 G3 直接 rebless**。若产物有错，错误会被固化成"正确"，之后门禁永远通过。

### 步骤 4 · 看结果

成功：

```
断言 139　PASS 139　FAIL 0　SKIP 0
  分组：复算 34/34　v3合理 18/18　禁用词(源) 17/17　…

✅ DoD 通过：可以交付
```

失败：

```
断言 139　PASS 137　FAIL 2　SKIP 0
  ✗ [复算] ★v3 费用明细合计（＋未单列手续费）＝ 信托费用支出合计　65,356,355.60＋0.00 vs 65,606,355.60
  ✗ [v3合理] ★v3 次级档 XIRR 落在 −20% ~ 80%　2.18

❌ DoD 未通过：不得交付
```

**FAIL 不是"门禁太严"，是数据真有问题。** 按第七节的表逐条排查。

### 步骤 5 · 已交付单复验（回归）

改过任何脚本后，所有已交付单都要重跑。批量脚本示例：

```python
import os, subprocess, sys
BASE = r"E:\<项目根>"
PROJ = ["惠元2021年第一期", "惠元2021年第二期", ...]
ok = 0
for d in PROJ:
    line = os.path.join(BASE, d, "产线")
    html = os.path.join(BASE, d, "03_报告产出", f"{d}_不良ABS穿透分析_v1.html")
    r = subprocess.run([sys.executable,
                        os.path.join(line, "scripts", "single", "repro_gate.py"),
                        "--html", html],
                       capture_output=True, text=True, encoding="utf-8", errors="ignore")
    print(f"{d:16s} EXIT={r.returncode}")
    ok += (r.returncode == 0)
print(f"通过 {ok}/{len(PROJ)}")
```

## 四、验收标准（硬指标）

| 项 | 标准 |
|---|---|
| G1 | 产物 sha256 与 `golden/report.sha256` 完全一致 |
| G2 | 版式+文案指纹与 `golden/spec.json` 一致 |
| G3 | **FAIL = 0**；SKIP 允许，但必须知道跳了哪几条、为什么 |
| 产物大小 | 约 200–220 KB（单文件自包含，无外链 css/js/图片） |
| 渲染 | 无横向滚动、无元素溢出、SVG 全部有尺寸与 viewBox、无 <9.4px 字号 |

## 六、口径铁律（错了整个报告就废了）

| 指标 | 唯一口径 | 常见错误 |
|---|---|---|
| 证券化率 | 发行规模 ÷ 入池本息费 | 用入池本金做分母 |
| 回收率 | 累计回收 ÷ 入池本息费 | |
| **处置费率** | **处置费用 ÷ 累计回收** | 用发行规模或入池做分母 |
| 达成率 | 实际累计回收 ÷ 中债预计回收（**金额 ÷ 金额**） | 用回收率百分比反推 |
| XIRR | 全周期真实现金流 IRR | 用票面利率替代 |
| XNPV 折现率 | 发行日 1 年期国债到期收益率 | 用统一 3% |
| 终局判定 | **信托计划是否终止** | 用"本金是否归零"（那是证券端终局，不是信托终局） |

**禁用词**（出现即 G3 FAIL）：折价率、预测XIRR、发行利差、约定资金成本率、已终局、
简单平均、处置费用占比、内部字段路径、本地路径。

**分布表单位坑**：`dist[*].bal` 是**万元**，`pool.balance_total` 是**元**。
算占比必须 `bal / (balance_total / 1e4)`，否则错 1 万倍，而且图内自洽看不出来。

## 七、FAIL 速查表

| FAIL 的断言 | 最可能的原因 | 查哪里 |
|---|---|---|
| 费用明细合计 ≠ 披露合计 | OCR 在科目名中间断行，某科目被丢 | 匹配前 `ns()` 去空白；看明细条数够不够 |
| 逐期分档本金合计 ≠ 清算兑付额 | 分层表某档清零时该格为空，按位置取值错位 | 改用兑付表「剩余本金值 × 发行额/100」 |
| 次级/优先 XIRR 超区间 | 上游分档数据错，XIRR 被污染 | 先查分档本金合计那条 |
| 余额末期未归零 | 末期未全额兑付，或该期解析失败 | 看 `_periods_raw.json` 该期是否有值 |
| 预测现金流合计 ≠ 中债预计回收 | 说明书两张表叠加，或分页整行重复 | 只去重"与首行完全相同"的行 |
| 预测现金流衔接断裂 | 漏取中间段，或 `-` 被当非数字丢弃 | `-`/`—` 按 0 处理 |
| 恒等式① 不成立 | 清算开始日负债构成与假设不符 | 逐项解析「…费为人民币 N 元」，别写死公式 |
| 资金平衡残差 >1 万 | 增值税口径（并入 vs 单列）搞错 | 看 `vat_included_in_fees` |
| 内容可见「X」失败 | 报告里没有这个数 | 构建器没把这个字段渲染出来 |
| G1 哈希不一致但 G3 全过 | 换行符（\r\n）或手改了产物 | 必须 `newline=""` 写 |

## 八、绝对不要做的事

1. **不要为了过门禁而放宽容差**。容差只能按"披露精度"调整，且要在注释写依据。
2. **不要手工填 payload**。字段缺失只有两条路：补取数器，或确认不适用后让断言 SKIP。
3. **不要在 G3 未过时 rebless**。那会把错误固化成基线。
4. **不要把备份放进 `skills/` 目录**。会被当成同名技能重复登记，导致加载到旧版。
5. **不要只验证一单就宣布完成**。改过脚本必须全量回归。
6. **不要用恒等式反推数据再拿恒等式验证**。那是循环论证。
