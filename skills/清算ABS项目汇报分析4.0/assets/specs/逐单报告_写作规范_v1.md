## 1. ★取值铁律（写每一个数字前先看这里）

**有效值 = base ∪ `supply.effective`（缺项取影子层）。** base 的 `forecast`/`recon` 是**原始解析态、按设计永久不被污染**，直接读会读丢补录成果。

| 报告内容 | 取值路径 |
|---|---|
| 项目名 / 银行 / 品种 | `key` / `bank` / `variety.cat`（判据 `variety.evidence_src`） |
| 设立日 / 清算日 | `setup_date` / `liquidation_date` |
| 入池本金 / 入池本息费 / 入池息费 | `pool.pool_prin` / `pool.pool_bsf` / `pool.pool_intfee` |
| **预计回收（有效）** | `supply.effective.forecast.total_rec_yuan`（若无则 `forecast.total_rec_yuan`）；保留 `unit_raw` |
| **预计逐期（有效）** | `supply.effective.recon.forecast_bucketed` |
| **达成率（有效）** | `supply.effective.recon.achievement`（若无则 `recon.achievement`） |
| 口径状态 | `forecast.missing` / `forecast.discarded`（base）与 `supply.effective.forecast` 是否存在，二者组合说明 |
| 优先档 / 次级档 XIRR | `xirr.senior.xirr` / `xirr.sub.xirr`（`xirr.computable=false` ⇒ 标「待核查」，不得硬算） |
| 回报倍数 | `xirr.sub.multiple` |
| 双层分配矩阵 | `alloc2.rows`（含 `label/role/src/values/cum`）、`alloc2.fee_labels`、`alloc2.fee_total`、`alloc2.security_total`、`alloc2.out_total`、`alloc2.rec_total` |
| 两表本金差 | `alloc.principal_diff` |
| 逐期现金流 | `periods[]`（`period/begin_date/end_date/pay_date/in/out/begin/end`） |
| 账龄 / 加权平均逾期 | `pool.wavg_overdue_m` / `dist.age`（若 `dist` 有该维度） |
| 缺口分级 | `supply.graded` + `disclosures[]`（**含渲染层徽章所述等级**） |
| 回源补录 / 冲突 | `supply.overrides[]` / `supply.conflicts[]` / `supply.effective` |

**强制**：
1. **每个数字在文末注明出处键名**（如 `recon.achievement`、`xirr.sub`、`alloc2.security_total`）。
2. **payload 里没有、需现算的比例**（如「处置费/回收」「月均回收率」）**必须写出计算式**、保留到分，且与 `复算_报告.md` 一致。
3. **凡对不上 payload 或复算报告的，一律写「待核」，不得写入数字。**
4. **金额一律「千分位 + 2 位小数」**；量级缩写用 `x.xx 亿` / `x.xx 万`；百分比 2 位小数。

## 2. 每份报告的 9 节（结构固定，标题逐字照抄）

```markdown
# {项目名} · 单项目穿透分析报告

> {银行} · {品种} · 设立 {setup_date} · 清算 {liquidation_date}
> 数据来源：payload.json（唯一真源）＋ 发行说明书/受托机构报告（回源补录）＋ 缺口清单
> 编制口径：金额单位元，保留至分；比例保留 2 位小数

## 一、项目核心指标速览
（表格，列：指标 | 数值 | 说明。至少含：入池本息费 / 入池本金 / 入池息费、发行规模（优先+次级，
 取自 `tranche.issue`）、证券化率、实际回收、预计回收（有效）、达成率（有效）、实际回收率、
 优先档 XIRR、次级档 XIRR、回报倍数、优先/次级本金累计兑付率、处置费累计、处置费占回收）

## 二、结论摘要（五个标准问题）
1. 次级档收益水平如何（XIRR / 回报倍数），为什么是这个水平？
2. 实际回收 vs 预计回收（达成率），是否达标？
3. 兑付 / 清算是否及时（是否提前、提前多久）？
4. 处置费用占回收比例，是否超合同上限？
5. 账龄与回收购置如何，回收是否前置？

## 三、次级档收益深度拆解
（收益绝对水平表：`固定资金成本 / 超额收益 / 未拆分额 → 占次级本金`；回报倍数；
 `alloc2` 现金流去向逐项勾稽；驱动因素逐一落到本单数字）

## 四、兑付与清算时点
（逐期兑付时间线：`periods[]` 的 pay_date + 优先/次级本金兑付进度；优先档/次级档何时兑完；
 与预期/法定期限的比较——**无披露的期限不得编造，标「未披露」**）

## 五、现金流去向（双层分配矩阵）
（照 `alloc2.rows` 原样展开：证券受偿〔优先档本金/利息/小计、次级档本金/收益合计/└固定资金成本/
 └超额收益/└未拆分额/小计、证券受偿合计〕＋费用与其他〔各费用科目/费用小计/转存下期/各项流出合计〕
 ＋参考行；**逐分勾稽**并注明 `alloc2.*` 出处）

## 六、处置费用
（`alloc2.fee_labels` 中「处置费用」累计、`处置费用 / 实际回收`、是否超合同上限；
 **合同上限比例须来自 `pool` 或披露；无披露则写「合同上限未披露」**）

## 七、账龄结构
（加权平均逾期 `pool.wavg_overdue_m`；`dist.age` 分布表（若有）；对回收率/回收速度的影响）

## 八、数据质量与缺口
（逐条列出 `supply.graded` 与 `disclosures[]` 的 A/A'/B/C/D 级 + 出处；`supply.conflicts`；
 `supply.overrides` 的**语义更正类**逐条；待核项）

## 九、数据口径与修订说明
（本单的：口径排除 / 标签错位更正 / 影子层补录 / 两表本金与利息差 / 舍入差 —— 逐条说明来源与影响；
 无则写「本单无口径修订」）
```

## 3. ★四类已知错误：逐单审计（**不得复现、不得漏报**）

| # | 错误 | 审计点 |
|---|---|---|
| 1 | **口径误取** | 任何「预计回收」必须确认是**有效 forecast**（`forecast.discarded` / `missing` + `supply.effective.forecast`）；若曾误取「池本息费余额滚动表」须说明 |
| 2 | **标签错位** | 分配表科目须按 **x 列位**重读；招元第八期第17期 base 整行上移、漏「税费支出」、把 `12,492,884.44` 错标为「审计费」（实为贷款服务机构报酬） |
| 3 | **标签未归一** | 科目 label 须经 `alloc_label_display` 归一后再归属；短名/长名不得落到不同行 |
| 4 | **断言自欺** | 凡「确无 / 未读取到」类措辞必须附**逐页证据**；写不出证据⇒标「待核」；已被回源补录的事项**不得**再标「报告确无」或「源文件缺失」 |
