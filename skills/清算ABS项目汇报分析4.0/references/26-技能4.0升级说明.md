## 二、4.0 相对 3.0 的五处升级

### 升级 1 · 新增 `scripts/pipeline/` 上游解析工具箱（最大变化）

3.0 只有 `scripts/single/`（payload → 报告）。实际做单时 70% 时间花在上游取数，
这部分经验原本散在各项目目录里，现在固化进技能：

```
scripts/pipeline/
  02_parse_prospectus.py   说明书   分档/资产池/分布/分配顺序
  03_parse_dist.py         说明书   8 维度分布（含扫描件坐标还原）
  04_extract.py            PDF      抽文本 + 文档归类
  05_parse_trustee.py      受托报告 逐期账户/兑付/流出
  06_parse_liquidation.py  清算文书 清算日/费用/兑付/回购
  07_parse_rating.py       评级报告 预计回收（中债资信）
  08_assemble.py           全部     → payload + metrics
  14_to_layout.py          payload  → payload_layout（补字段 + flows）
  _numfix.py / _g1.py / _recon.py / _scope_check.py / _ocr_*.py / _xy_dist.py
```

详见 **`references/25-上游解析工具箱.md`**。

### 升级 2 · 路径全部参数化（可移植性的前提）

原先 3 个脚本写死了 `C:\Users\<用户名>\.workbuddy\skills\清算ABS项目汇报分析3.0`
和 `E:/兴业银行兴瑞冒烟测试`，换个用户名/盘符/批次就废。4.0 全部改为环境变量：

| 变量 | 含义 | 缺省 |
|---|---|---|
| `ABS_SKILL` | 技能根 | 由脚本位置反推 |
| `ABS_ASSETS` | 单期输入目录（payload/metrics/css/peer） | `<技能根>/assets/single` |
| `ABS_BATCH` | 批次根（各期子目录的父目录） | 由 `--proj` 的父目录推出 |
| `ABS_PREFIX` | 期次目录名前缀（兴瑞/建鑫/惠元/和萃） | **必须显式给出**，不沿用他行品牌名 |

`14_to_layout.py --all` 原先写死 `n.startswith("建鑫")`，4.0 改为 `--prefix` 必填。

> 这是「移植到其他智能体」的硬前提：不同机器上盘符、用户名、目录名都不同。

### 升级 3 · 新增 `references/23-四行体例差异台账.md`

把「同一件事在不同行不同写法」全部列表。**写解析器之前先查这张表。**
覆盖：三种清算报告体例、次级固资 A/B 两体例、期次排序键、年度报告混入、
预计回收取源方向相反、分布表列序相反、预测表单位不同、累计回收会倒退、
术语与结构差异速查、每接一家新行的 10 步检查顺序。

### 升级 4 · 新增 `references/24-反模式清单与门禁盲区.md`

12 个反模式，每条对应一次真实缺陷，都带实测数字。核心论点：

> **三层门禁查的是「自洽」，查不出「张三戴了李四的帽子」。**
> 最硬的证据：矩阵档位列「优先」→「证券」，文件大小一模一样（209,003 B 分毫不差），
> 只有 SHA256 不同；G1/G2 全过，G3 没有一条断言管这个列 —— 只有人眼能发现。

### 升级 5 · 断言与字段契约增补

| 新增 | 在哪 | 抓什么 |
|---|---|---|
| A1 `XIRR 可由现金流复算`（1bp） | `verify_single.py`（优先/次级各一） | 两套现金流并存（实测差 −648bp） |
| A2 `清仓回购已发生则起算日必存在`（改写） | `verify_single.py` | 泛指提及误判 / 只给通知书日 |
| `recovery_includes_buyback` 开关 | `verify_single.py` 资金平衡 | 回购价款重复计入（实测残差 +322,969.87） |
| `sub_fixed_total` / `sub_excess_total` 呈现 | `build_single.py` XIRR 卡片 | 次级资金成本不可见（原先 8 单空缺） |
| 存续期 < 18 月提示 | `build_single.py` | 年化 XIRR 被误读为长期收益率 |

字段契约（`references/19`）同步补了 8 个 4.0 字段及其缺失后果。

## 三、兼容性：**老交付件一个字节都不变**

这是本技能历次升级最硬的一条纪律。

| 检查 | 结果 |
|---|---|
| 惠元第三期 G1 | ✅ 命中基线 `deeef1e06070013a…`，**205,040 B 未变** |
| 惠元第三期 G2 | ✅ 通过 |
| 惠元第三期 G3 | ✅ FAIL = 0 |
| 3.0 → 4.0 文件级 | ✅ 3.0 的 120 个文件**全部保留**，只删了 2 个 `.bak` 备份 |

隔离机制：

1. **所有会改数值的新逻辑都必须带 payload 开关**（缺省＝老行为）；
2. 卡片新增的拆分行只在 `M.get("sub_fixed_total")` 存在时才渲染；
3. 存续期提示同时要求 `sub_fixed_total` 存在（惠元 life=12 但无该字段，故不触发）。

> 教训（真金白银）：一项费用校准逻辑未加开关，让惠元 G1 **差 1 字节**
> （审计费 49→47、未归集差额 −580.45→−531.45）。1 字节也是回归。

## 五、4.0 仍然没解决的

如实记录，不要当成已解决：

1. **扫描件版面还原不是万能的**。兴瑞2021一期 creditlimit / overdue / region / occupation
   四个维度版面未构成完整表，坐标法也还原不出（合计差 38.5 亿）→ 置灰，SKIP 9 条。
2. **A/B 体例判定依赖清算报告总额**。存续期单没有清算报告 → 只能按单期猜，
   此时应记 `sub_fixed_total = None` 并在报告里写"不可拆"，不要硬算。
3. **门禁查不出列语义错标**（反模式 12 的附表最后一行）。只能靠人眼 + 交付前自查表。
4. **法定到期日无真值时靠「成立日 + 5 年」推算**。这是近似，必须在表里标注来源为"推算"。
5. **上游解析器是按四行体例调的**。第五家银行（如浦发/平安/广发）很可能有第三种固资体例、
   第四种清算报告体例。接新行时**先跑 `23` 的 10 步检查**，不要假设「应该差不多」。
