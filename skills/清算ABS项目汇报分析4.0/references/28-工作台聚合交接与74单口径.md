# 28 · 工作台聚合交接与 74 单口径（4.2 / 2026-11-06）

> 本文件只回答一件事：**单项目报告做完以后，怎样把结果交给「清算ABS多行工作台聚合展示」技能，聚合成 74 单 / 5 家银行的工作台。**
>
> 单项目报告怎么从 PDF 做到 HTML，仍走本技能产品线 A；工作台怎么排图、切片、门禁，走第二技能。两个技能不要互相重写。

---

## 1. 两个技能的边界

| 技能 | 输入 | 输出 | 不做什么 |
|---|---|---|---|
| 本技能（`清算ABS项目汇报分析4.0`） | 单项目 PDF、发行说明书、受托报告、清算报告、评级报告 | 单项目 `payload.json` / `metrics.json` / 八节 HTML / `_assert_single.json` | 不做 74 单跨行对比页 |
| 第二技能（`清算ABS多行工作台聚合展示`） | 74 个项目目录（至少 `02_提取数据/*.json` + `03_报告产出/*.html`） | 单文件多行工作台 V9（13 张 ECharts + 1 个 HTML 现金流分配板） | 不重新解析 PDF、不改单项目报告数值 |

**交接原则：单项目不过 G1/G2/G3，不进入工作台。** 工作台不是“展示层兜底”；它只聚合已验收的单项目结果。

## 2. 项目目录契约（单项目产出侧）

每个项目目录必须至少包含：

```text
<项目名>/
├── 01_下载文档/                        原始 PDF（归档，工作台不读）
├── 02_提取数据/
│   ├── metrics.json                    ★ 39 个已算指标；工作台行数据主源
│   ├── payload.json                    ★ 项目元信息 / 资产池 / 分档 / 期次 / 分配
│   └── _trustee_parsed.json            受托报告解析中间态（可选）
├── 03_报告产出/
│   ├── <项目名>_不良ABS穿透分析_v*.html  ★ 报告正文；工作台报告查看器与现金流解析源
│   └── _assert_single.json             ★ 单项目断言结果；FAIL/SKIP 清单
└── 产线/                               构建脚本快照（可选，便于回溯）
```

缺 `metrics.json` 或 `payload.json`：工作台直接判 **INPUT_MISSING**，不补、不猜。
缺 `03_报告产出/*.html`：报告查看器空、现金流/回购解析为 0，仍不得用其他项目兜底。

## 3. 工作台 74 行的数据字典

工作台总表 `_rows_all.json` 是 74 行数组。一行一只项目，字段如下（`null` 表示未披露，不用 0 冒充）：

| 字段 | 类型 | 含义 / 公式 | 来源 |
|---|---|---|---|
| `bank` | string | 中信银行 / 招商银行 / 建设银行 / 兴业银行 / 农业银行 | `payload.meta.originator_short` |
| `proj` | string | 项目简称（工作台唯一键，去空格匹配） | `meta.display_name` |
| `variety` | string | 信用卡不良 / 个人经营不良 / 个人消费不良 / 住房抵押不良 | `meta.variety`，经正文复核 |
| `issue_date` | YYYY-MM-DD | 发行日 / 起息日 | 说明书 |
| `legal` | YYYY-MM-DD | 法定到期日 | 说明书 |
| `term` | YYYY-MM-DD | 信托终止 / 清算完成日（存续单可为空） | 清算报告 |
| `state` | `settled` / `open` | 已清算 / 存续 | 清算文书 + 受托报告 |
| `life` | int 月 | 存续月数（已清算：终止−发行；存续：报告期末−发行） | `metrics.life_months` |
| `issue` | 元 | 发行规模 | 发行结果 / 说明书 |
| `pool` | 元 | 入池本息费 | 说明书 / 评级 |
| `sec_rate` | 0–1 | 证券化率 = `issue / pool` | 计算 |
| `sub_pct` | 0–1 | 次级占比 = `sub_issue / issue` | 计算 |
| `coupon` | 0–1 | 优先档票面 | 发行结果 |
| `recovery` | 0–1 | 回收率 = `recovered / pool` | 清算 + 受托 |
| `exp` | 0–1 | 预计回收率 = `recovered / achieve / pool`；**不得由回收率反推后当披露值** | 中债评级 / 达成率 |
| `achieve` | ratio（可 >1） | 达成率 = `recovery / exp`（金额÷金额）；1.013 = 101.3% | 计算 |
| `dispose` | 0–1 | 处置费率 = 已报销处置费用 / 累计回收 | 受托 + 清算 |
| `servicer` | 0–1 | 服务报酬率 = 贷款服务报酬 / 累计回收 | 受托 |
| `fee` | 0–1 | 费用合计率 = `fee_total / recovered` | `metrics.fee_total_rate` |
| `sen_xirr` | 0–1 | 优先档 XIRR | 现金流复算 |
| `sub_xirr` | 0–1 | 次级档 XIRR（已实现口径） | 现金流复算 |
| `mult` | x | 次级回报倍数 = Σ次级现金分配 ÷ 次级实际认购金额 | 现金流复算 |
| `n_loans` / `n_bor` | int | 入池笔数 / 借款人 | 说明书 / 评级 |
| `avg_loan` | 元 | 平均入池本息费 | 说明书 |
| `wavg_od` | 月 | 加权平均逾期 | 说明书 |
| `sub_bal` / `doubt` / `loss` | % | 次级 / 可疑 / 损失类占比（加权） | 资产池五级分类 |
| `sub_amt` / `doubt_amt` / `loss_amt` | 万元 | 三类余额 | 资产池 |
| `recovered` | 元 | 累计回收 | 受托 / 清算 |
| `sen_issue` / `sub_issue` | 元 | 两档发行规模 | 发行结果 |
| `line` | string | 条线短名（信用卡 / 个人经营 / 个人消费 / 住房抵押） | 品种映射 |
| `year` | string | 发行年份 | `issue_date[:4]` |
| `fails` / `skips` | array | 单项目 FAIL / SKIP 摘要（允许空数组） | `_assert_single.json` |

**口径顺序：** 中债资信评级报告 > 发行说明书 > 受托机构报告 > 清算审计/专项复核 > 其他（仅参考）。
**单位：** 池/发行/回收/两档规模一律“元”；资产质量余额一律“万元”；百分比以 0–1 小数存储，展示时 `pct()`。
**排序：** `issue_date` 升序；同一天按项目名稳定排序。不得用期次字符串排序（10 期会排到 2 期前）。

## 5. 单项目 → 工作台行：桥接脚本

本技能提供：

```text
scripts/export_workbench_row.py
```

用法（在任意目录执行）：

```bash
python -X utf8 scripts/export_workbench_row.py \
  --project "E:\农业银行冒烟测试\农盈利信2021年第一期" \
  --canonical "E:\不良ABS四行修复_DSH\11_工作台\_rows_all.json" \
  --out "./workbench_row.json"
```

它做四件事：

1. 校验项目目录、`metrics.json`、`payload.json`、报告 HTML；
2. 从 `metrics` / `payload` 映射核心 30 个字段；
3. 从 canonical 行补齐资产质量余额、`fails/skips`、`state` 等非 metrics 字段；
4. 输出一行 JSON + 该行 SHA256 + 字段缺失清单。

`--strict`：缺任何必填字段即 EXIT=1；不加时保留 `null` 并打印 WARN。
批量聚合由第二技能 `scripts/aggregate_rows.py` 负责；本脚本只做单行桥接。

## 6. 两技能联合门禁

### 6.1 单项目侧（本技能）

```bash
python -X utf8 scripts/single/repro_gate.py --html "<项目>\03_报告产出\<项目>_不良ABS穿透分析_v*.html"
```

- G1：HTML SHA256 vs 单项目 `golden/report.sha256`（或项目 `_assert_single.json` 里记录）
- G2：逐节版式 + 文案指纹
- G3：137–144 条语义断言，FAIL=0；SKIP 不能当 PASS

### 6.2 行数据侧（第二技能）

```bash
python -X utf8 scripts/aggregate_rows.py --projects-root "<项目根>" --out "dist/_rows_all.json"
python -X utf8 scripts/gate.py --html "dist/不良ABS..._V9.html" --rows "dist/_rows_all.json"
```

行门禁至少检查：

- 74 行；5 家银行；70 settled / 4 open；
- 74 个项目名唯一；无 NaN/Infinity；日期可解析；`issue_date ≤ term`；
- `recovery`, `achieve`, `sec_rate`, `sub_pct` 在 0–1；`life` 为正；
- `exp ≈ recovery / achieve`（±1e-9）；
- 单项目 `fails` 为空；任一 FAIL 单不得进工作台；
- 行数据 SHA256 与 `_rows_all.sha256` 一致。

### 6.3 工作台产物侧（第二技能）

- **G1 字节级**：`workbench_V9.html` SHA256 = `8ae21fd0266387ae9fde9b00ceecf432bcac4ed864eaf7a1e2e11a680d037593`，11,385,763 B；
- **G2 数据/结构**：`V3_FULL` 74；`REPORTS` 74；13 张 ECharts；`__v3cashflowParsed=74`；`.cf-row=8`；
- **G3 交互**：无 JS 错误；单选/Ctrl 多选；银行页；矩阵；现金流行点击；报告查看器打开/返回；14 图均存在。

> 任一 G 不通过：**不交付**。不要用“截图看起来对”代替。

## 8. 从零到一的顺序（两技能串起来）

```text
① 装本技能（单项目）
② 对每个项目：pipeline 取数 → build_single → repro_gate（G1/G2/G3）
③ 保存 02_提取数据 + 03_报告产出 + _assert_single.json
④ 装第二技能（工作台）
⑤ aggregate_rows.py 汇总 74 行；行门禁通过
⑥ build_workbench.py 重建 V9；G1/G2/G3 通过
⑦ 版本号 V1→V9 保留；更新版本索引；打包
```

**不可跳步：** 没有单项目验收，就没有合法行数据；没有行数据门禁，就没有工作台。

## 9. 常见失败

| 现象 | 根因 | 处理 |
|---|---|---|
| 工作台 74 行但某行数值空 | `metrics.json` 缺字段 / 报告未生成 | 回单项目重跑；不要补 0 |
| 现金流 0 行 | 报告 HTML 缺 `data-label/data-cum` 矩阵 | 检查单项目 ④ 现金流分配节；不要跨项目兜底 |
| 回购切片全空 | 报告正文缺“是否回购” | 检查单项目报告；工作台不猜 |
| 行数 67/73 | 项目目录漏、`proj` 名不一致 | 用 `proj` 去空格匹配；核对 74 清单 |
| 工作台 G1 失败但界面正常 | 改了 V9 HTML 或源码不同步 | 从 V9 基线 + `_v3` 源重建；不要手改 |
| 工作台图表数 12 | 现金流 HTML 板未渲染 / 某 ECharts 构建异常 | 查控制台；`__v3charts` 应为 13 |
