# 00 · 从零到交付 · 完整复现手册

> **这是最重要的一份。** 目标：让一个从没做过这个项目的人/agent，能按本文从原始数据走到 v11 水平的成品。
> 缺任何一环都出不来「冷灰蓝账本」质感的成品。

---

## 〇、必须先理解的一件事：交付物是「两层」不是「一层」

```
┌─ 上游 BASE（大体量、已有、不要重写）────────────────────────┐
│  逐单 JSON / 说明书 PDF                                      │
│    → build_liq28_payload.py   → _校验件/payload.json         │
│    → pen_report_liq28.py      → 清算28单_单项目穿透_报告.html │
│         （28 单 × 8 节 + SVG，约 2.76 MB）                    │
└──────────────────────┬──────────────────────────────────────┘
                       │ 适配
         adapt_28to3.py → 设计资产/payload_28.json
                       │
┌──────────────────────▼──────────────────────────────────────┐
│  增强层（本技能主体，v2 模块）                                │
│  00_ctx 10_overview 20_profile 30_compare 40_audit           │
│  50_charts 60_assets 70_wording                              │
│    → build_v2.py   组装                                      │
│    → verify_v2.py  144 断言验收                              │
│    → 清算28单_不良ABS穿透分析报告_v11.html（4.01 MB）         │
└─────────────────────────────────────────────────────────────┘
```

**两条路线**：
- **路线 A（推荐）**：BASE 已存在 → 只做增强层。**本项目走的就是这条**。省掉数月的数据治理。
- **路线 B（从零）**：BASE 不存在 → 先复现上游管线（见 `08-上游管线与口径裁定.md`）。**工程量约等于增强层的 3–5 倍**。

> ⚠ 不要试图跳过 BASE 直接写增强层 —— 增强层是**给 BASE 打补丁**（scope_css、DOM 钩子、SVG 重绘），没有 BASE 全部失效。

**BASE 与原始数据**：

### 步骤 1 · 数据门控（必做，30 分钟）

```bash
<python> <skill>/scripts/selfcheck_data.py --payload <BASE>/_校验件/payload.json
```

输出字段可得率 + 已知缺陷。**必须读一遍 `01-数据契约.md`**，记住：
- **不存在**的字段：预测 XIRR / 发行利差 / 约定资金成本率 → 永不画
- `subFixed` 只有 8 单真实单列
- 6 单处置费用重复计入

### 步骤 2 · 锁口径（1 小时）

读 `02-口径纪律.md` + `_校验件/增量口径裁定_v9.md`（最新）。
把口径表写进 `00_ctx.py` 的 `UNIT_POLICY` 与各模块头部注释。

### 步骤 3 · 搭骨架（2 小时）

复制 `脚本\v2\` 目录，按 `03-报告架构.md` 改：
1. `00_ctx.py`：路径、`OUT_NAME`、`TOKENS`、`build_v2_data()`（含 `WF`/`DIST` 注入）
2. `build_v2.py`：模块加载 → scope_css → 视图组装 → 写入
3. `verify_v2.py`：静态断言 + 无头浏览器渲染断言骨架

**先让它跑通一个空壳**（只注入 CSS、不改 DOM），确认 BASE 能正常打开、侧栏能切。

### 步骤 4 · 逐模块实现（按依赖顺序）

| 顺序 | 模块 | 依赖 | 验收 |
|---|---|---|---|
| 1 | `50_charts.py` | BASE 的 SVG 结构 | 图表能重绘、单位统一 |
| 2 | `60_assets.py` | 50 的重绘结果 | 卡片分行、viewBox 自适应 |
| 3 | `10_overview.py` | `payload_28.json` | 总览看板、筛选器 |
| 4 | `20_profile.py` | BASE 的 28 单 DOM | 5 类分组、面板重排 |
| 5 | `30_compare.py` | `__V2.WF/DIST` | 横向对照 5 板块 |
| 6 | `40_audit.py` | audit_payload | 明细与底稿独立栏目 |
| 7 | `70_wording.py` | **最后跑** | 文案去技术化、终局性、路径脱敏 |

> **70_wording 必须最后执行**（文案改写优先级最高），在 build 里 JS 顺序放最后。

### 步骤 5 · 视觉打磨（最容易返工的一步）

读 `07-设计系统_冷灰蓝账本.md`。**不要自创配色**，用 `三单_design.css` 的令牌。

关键检查：
- 材质三层（canvas/paper/paper-2）分层，**不靠边框**
- 衬线只用于陈述，数字一律无衬线 + `tabular-nums` + 右对齐 + 单位小字
- 语义色只在真异常时出现
- 圆角 6/10/14，胶囊 999px

### 步骤 6 · 断言验收（必须 0 FAIL）

读 `10-验收断言清单.md`。**至少覆盖**：
- 禁用词 0（折价率/预测XIRR/倒算率/已终局/内部编码/本地路径）
- 单位/量级一致
- 缺失显示「—」
- 布局（等高、无溢出、无横向滚动、字号）
- 折叠默认收起、筛选可用
- **上一轮断言全部仍 PASS**

### 步骤 7 · 出图 + 留痕

```bash
# 预览图（无头 Edge）
msedge --headless=new --disable-gpu --no-sandbox --hide-scrollbars \
       --virtual-time-budget=27000 --window-size=1600,1750 \
       --screenshot=<out>.png "file:///<test>.html"
```
- 截图前注入脚本 click 目标视图；**若目标不在页面顶部，用「从目标向上找到 view 的直属子节点，隐藏其前面的兄弟」**（本项目验证有效）
- 写 `README_v<N>_精修版说明.md`
- 预览图放 `预览图v<N>\`

## 二、每次迭代的固定动作

1. **核实用户点评**（约 20% 是旧版信息或误读，不要照单全收）
2. 先跑数据验证，再动手
3. 分派 agent（若大改）
4. 组装 → 断言 → 出图 → README
5. **重命名交付物**（v2…v11，不覆盖）

## 三、路线 B（从零）额外步骤

见 `08-上游管线与口径裁定.md`。核心顺序：

```
① 采集：说明书 PDF → 逐单 JSON（flows_all / liq_dist / liq_info）
② 对齐：alias_map.yaml 做字段别名映射
③ 归一：build_liq28_payload.py → payload.json（含 9 类口径裁定）
④ 渲染：pen_report_liq28.py → BASE HTML（28 单 × 8 节）
⑤ 适配：adapt_28to3.py → payload_28.json
⑥ 增强：本手册步骤 3–7
```

⚠ ②③ 是**最耗时**的（口径裁定 v1–v9 共 9 轮），且必须**回源说明书页码**逐项核对。

## 四、绝对不能省的 8 件事

| # | 事项 | 后果 |
|---|---|---|
| 1 | 数据门控 | 画了不存在的字段 → 整份报告不可信 |
| 2 | 口径锁定 | 同一指标两个分母 → 审阅者一眼看穿 |
| 3 | 缺失显示「—」 | 显示 0 会被当成真值 |
| 4 | 渲染后断言 | 客户端改写后源文件仍有原文，静态断言全过但用户看到的是旧的 |
| 5 | 跨图量级校验 | 「亿」标「万」时图内单位词完全自洽，同图断言抓不到 |
| 6 | 标签配平（build 层） | 模块 HTML 多一个 `</div>` 会把宿主 `.main` 提前闭合 → 视图"消失" |
| 7 | 每版重命名 | 覆盖旧版 = 丢掉回滚能力 |
| 8 | 遗留问题如实记录 | 假装全解决 = 下一轮返工 |
