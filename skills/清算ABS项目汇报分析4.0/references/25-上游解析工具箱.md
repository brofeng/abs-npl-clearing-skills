# 25 · 上游解析工具箱（scripts/pipeline/）

> **4.0 新增。** 3.0 只带「下游成稿器」（`scripts/single/`，把 payload 变成报告）。
> 实际做单时，**70% 的时间花在上游取数**：从 681 页说明书、N 份受托报告、
> 两种清算报表、扫描件评级报告里把数抠出来。4.0 把这套解析器一并固化。

## 一、全链路

```
<批次根>/
  兴瑞2021年第一期/                 ← 单期目录（--proj 指向它）
    01_下载文档/                    ← 中债官网原始 PDF
    02_提取数据/
      文本/                         ← 可直取文本的 PDF → .txt
      OCR/                          ← 扫描件 → .ocr.txt
      *_parsed.json                 ← 各类解析中间产物
      payload.json  metrics.json    ← 最终成稿输入
    03_报告产出/                    ← html + golden/
```

```
02_parse_prospectus.py   说明书   → _sm_parsed.json      分档/资产池/分布/分配顺序
03_parse_dist.py         说明书   → _dist_parsed.json    8 维度分布（含扫描件坐标还原）
04_extract.py            PDF      → 文本/ 或 OCR/        PDF 抽文本 + 文档归类
05_parse_trustee.py      受托报告 → _trustee_parsed.json 逐期账户/兑付/流出
06_parse_liquidation.py  清算文书 → _liq_parsed.json     清算日/费用/兑付/回购
07_parse_rating.py       评级报告 → _rating_parsed.json  预计回收（中债资信）
08_assemble.py           全部     → payload.json + metrics.json
14_to_layout.py          payload  → payload_layout.json（补齐版式所需字段 + flows）
```

执行顺序：`02 → 07 → 03 → 04 → 05 → 06 → 08 → 14 → build_single → verify_single`

> 少数步骤有依赖：05 需要 02 的发行额（判列序、判优先档是否付清）；
> 06 需要 02 的发行额；08 需要前四者的全部产物。

## 二、两条硬规则

### 规则 1 · 每单独立 stage

`14_to_layout.py --stage` 输出目录**必须按单独立**。共用目录会把上一单的数据混进下一单，
且这种污染在断言里看不出来（数字都自洽，只是来自别的单）。

```bash
python 14_to_layout.py --proj <单期目录> --stage <批次根>/_stage/<单期目录名>
```

### 规则 2 · 批量编排用 `_build_all.py`

```bash
# 环境变量优先，不写死盘符/用户名/品牌名
export ABS_BATCH="E:/兴业银行兴瑞冒烟测试"
export ABS_PREFIX="兴瑞"
python _build_all.py
```

批量脚本做三件事：逐单跑 6 个解析步 → 独立 stage → 构建 + 断言，
结果落 `_<批次>_all.json`，单点失败不影响其他单。

## 三、各脚本的关键判据（改动前必读）

### `02_parse_prospectus.py`

| 判据 | 要点 |
|---|---|
| 品牌名 | 固定 **2 个汉字**：`([\u4e00-\u9fa5]{2})(\d{4})年第([一二三四五六七八九十\d]+)期`。用 `{2,}` 会吃出「元兴瑞」 |
| 品种序 | **信用卡 > 消费**（兴业原文「信用卡个人消费类不良贷款」含"消费"，判序错了会误判品种） |
| 发行规模下限 | `1e6`。否则「2023」（年份）会被当金额读进发行额 |
| 机构名 | 按「作为发起机构」前**保留换行**的行走，并 `^...$` 锚定。否则前缀污染出「福建省兴业银行」 |
| 目录过滤 | 必须真有点号：`[ \t]*[.．]{4,}`。用 `[\s.]{4,}` 会把正文的 4 个空白当目录 |

### `03_parse_dist.py`

| 判据 | 要点 |
|---|---|
| 章节起点 | `_dist_chapter_start()` 自适应。**不能写死 `lo=120`**（兴业分布章不在 120 页后） |
| 列序 | 按**表头动态定位**，且同写法取**最后一次**（中信与招行列序相反，见 `23` 第六节） |
| 区间标签 | `is_label` 先认区间（`30 万元以上`、`[0,4]`）再判表头词 |
| 未还原维度 | 记 `kind="scan-unparsable"` 并写**真实原因**，不得写「说明书未披露」 |

### `05_parse_trustee.py`

| 判据 | 要点 |
|---|---|
| 期次排序 | **本期期末日** > 结息日 > 支付日（见 `23` 第三节） |
| 年度报告剔除 | 支付日缺失 ＋ 付息＝前 k 期之和（见 `23` 第四节） |
| 次级固资 | A/B 两体例，**单期判不出**，交给 08 用清算总额反推 |
| 余额链 | 以「剩余本金」重建逐期兑付额（扫描件常把"兑付前本金"整格印成发行总额） |
| 支付日缺失 | 回退期末日，记 `pay_date_basis` |

### `06_parse_liquidation.py`

| 判据 | 要点 |
|---|---|
| 体例分派 | 见 `23` 第一节的三个 `if` |
| 费用窗口 | 用 `rfind("信托税费支出情况")`——审计意见段会先引章节名清单 |
| `负债合计` | 优先于「其他应付款」（附注号会粘连：`其他应付款 9 60,000.00` → 960,000） |
| 已分配信托利润 | 合理性判据：不得超过可供分配（`9 12,426,608.99` 是附注号粘连） |
| OCR 多读位 | `合计 − 分项` 反解（`4，704.635` → 4,704,635，100~10000 倍） |
| 回购价款 | 三种情形分开：明示金额 / 只披露事实 / 全文泛指（见 `23` 第二节末） |

### `08_assemble.py`

| 判据 | 要点 |
|---|---|
| 跨行隔离 | 任何「会改数据」的新逻辑必须加 payload 开关（如 `fee_calibrated`），否则污染他行已过基线的交付件 |
| 次级固资 A/B | 用清算总额反推体例，逐单自适应 |
| 负残差 | 记 `sub_reconcile_gap`，**不挂清算日、不调整逐期** |
| 同科目异写 | 先合并键再校准（否则同一科目记两遍，矩阵 111%） |

### `14_to_layout.py`

| 判据 | 要点 |
|---|---|
| flows 生成 | 逐期挂「本金 + 固资 + 超额」，仅 residual 挂清算日（见反模式 4） |
| BASE 语义 | 是**批次根**（各期子目录的父目录），不是技能目录 |
| 路径 | 全部走环境变量 `ABS_SKILL` / `ABS_BATCH` / `ABS_ASSETS`，不写死盘符 |

## 四、扫描件处理（OCR + 坐标还原）

### 4.1 OCR 提速

引擎：**rapidocr**（`Python312` 环境已装）。实测 **16.6 秒/页**。

> ⚠ 若跑到 85 秒/页，不是引擎慢，是**残留的 PopupWindow / LeAppOM 进程抢 CPU**，
> 杀掉后立即恢复。别急着换引擎。

### 4.2 坐标法还原分布表（`_xy_dist.py`）

扫描件的分布表常是**转置 + 并排 + 表头横向分散 + 跨页**，纯文本法无解。
三层切分：

1. **按 x 间隙切并排**（阈值 = 间距中位数 × 2.2）
2. **整页 cell 按表 x 范围裁剪**（页级裁剪，避免 x 分桶混表）
3. **数据行连续分段，遇「合计」收尾**（合计行必须收段）

### 4.3 ★ 硬校验：余额合计 = 入池本息费

每个维度还原后必须过这道校验（误差 < 200 元）才采信；
不过则**置灰并写真实原因**（`REJ` 记录进 `_dist_xy.json`）。

> 这一条挡住了大量「看起来像表、其实是乱码」的结果。
> 兴瑞2021一期 creditlimit 坐标合计差 38.5 亿 → 直接置灰，不猜。

## 五、代理脚本

| 脚本 | 用途 |
|---|---|
| `_numfix.py` | 金额粘连切分（DP + 12 位护栏 + 前导零罚分） |
| `_g1.py` | 逐单 G1 哈希门禁（同 stage 重建 → SHA256 比对 → 更新 golden） |
| `_recon.py` | 逐科目对账（**反模式 7 的唯一解药**） |
| `_scope_check.py` | 项目池范围核定（哪些该做、哪些已做、为什么不做） |
| `_ocr_*.py` | OCR 分页/整册/单文件工具 |

### `_numfix.py` 的护栏值

**11 位（百亿）是安全上界**，12 位太松：两列小额粘连容易正好拼成 12 位
（24,159.91 × 2 → 2415 亿）。

### `_scope_check.py` 的三源交叉

范围核定不能靠印象。三源交叉：

1. `NPL项目_资产类型与清算_全表.csv` —— 项目池 + 是否已清算
2. `中债清算公告_全量.json` —— 清算审计报告 / 受托报告期数 / 成立公告日
3. 本地已做单的 `payload.meta` —— 发行日、法定到期日真值

判定口径：`发行日 ≥ 2021-01-01` 且（已取得清算文书 或 法定到期日 ≤ 基准日）。

> **法定到期日优先取真值**（说明书）；无真值时按「成立公告日 + 5 年」推算，
> 并**明确标注「推算」**，不得当真实值用。
