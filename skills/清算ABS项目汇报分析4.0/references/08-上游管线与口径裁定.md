## 四、BASE 生成器的关键实现（复现时参考）

| 要点 | 说明 |
|---|---|
| **单文件架构** | `<script id=payload>` 内嵌 JSON + 纯前端渲染，零外部依赖、离线双击即开 |
| **渲染策略** | 侧栏切换 → `requestAnimationFrame` 内 `renderCharts(view)` 重绘 SVG |
| **`display:none → block` 后必须重测 `clientWidth` 重绘** | 否则 viewBox 失真 |
| **母版引擎复用** | CSS 令牌 / `foldHTML` / `renderCharts`+`hostW` / `nf/yi/wan/pc/S/scrub` / `CHARTS` 注册表 / `IntersectionObserver` 入场 / `statusOf(p)` 状态函数 |
| **分配矩阵行序** | 必须在 `build_liq28_payload.py::build_alloc2` 内完成，带装配护栏 |

## 六、路线选择建议

| 情形 | 选择 |
|---|---|
| BASE 已存在且结构完好 | **路线 A**（只做增强层） |
| BASE 存在但数据有缺陷 | 路线 A + 回源修补（改 `build_liq28_payload.py` 重跑） |
| 完全没有 BASE | **路线 B**，且要做好数月投入的准备 |
| 只换品种/换数据集（同结构） | 复用全部脚本，只换 `payload.json` 与 `OUT_NAME` |

## 七、从零时最容易低估的工作量

1. **字段别名对齐**（`alias_map.yaml`）—— 28 单说明书用词不统一
2. **口径裁定**（v1–v9 共 9 轮）—— 每轮都要回源页码
3. **分配矩阵行序**（拓扑排序实证）—— 不能靠猜
4. **池字段 OCR 噪声**（38 条非标准键/单）—— 要排除但不丢弃
5. **多口径预测**（中债/中诚信/世联）—— 要注明主口径与敏感性
