# 21 · 技能 3.0 升级说明（从 2.0 迁移）

## 一、一句话

2.0 是**单项目专版**：断言里硬编码了惠元 2021 年第三期的数值，换一单必然 FAIL。
3.0 把它改成**跨单通用**，并把中信银行 15 单实操中暴露的 **3 类真实漏洞**补进门禁。

| | 2.0 | 3.0 |
|---|---|---|
| 断言数 | 113 | **138（旧 payload）／139（字段齐全）** |
| 断言是否跨单可复现 | ❌ 硬编码第三期数值 | ✅ 全部由 payload/metrics 驱动 |
| XIRR 合理性检查 | ❌ 无 | ✅ 有区间断言（抓 218% 这类错） |
| 费用明细是否对平 | ❌ 不查 | ✅ 查（曾漏 25 万） |
| 逐期分档 vs 清算报告 | ❌ 不查 | ✅ 查（曾多算 6,910 万） |
| rebless 保护 | ❌ 直接把当前产物定为基线 | ✅ 先过 G3 才允许，且留痕 |
| 字段缺失 | 💥 中途 KeyError 崩栈 | ✅ 前置契约检查，EXIT=2 + 明确清单 |
| 诊断信息 | FAIL 只给描述 | ✅ FAIL/SKIP 分流 + 分组统计 + 残差量化 |

## 二、为什么必须升（2.0 在最关键的地方是空转的）

做中信 15 单时，2.0 的门禁**全部通过**的三份报告，实际上都有硬伤：

| 单 | 2.0 的判定 | 实际情况 |
|---|---|---|
| 2022 年第四期 | ✅ 113/113 | 优先档逐期本金多算 **6,910 万**，次级 XIRR 虚高 **218%** |
| 2022 年第六期 | ✅ 通过 | 漏「受托机构报酬」**25 万** |
| 2023 年第七期 | ✅ 通过 | 同上，漏 25 万 |

**根因不是"断言写少了"，而是断言只做了"自洽检查"**：它校验了清算报告一侧的数字对不对，
却没校验"逐期加总"与"清算报告"是否一致；校验了各科目名称在不在，
却没校验"明细合计"与"披露合计"是否对平。

一句话：**两个都自洽，但互相对不上，门禁就看不见。**

## 四、兼容性

### 已有 2.0 项目能直接用 3.0 吗？

能，但要先跑体检：

```bash
python scripts/single/repro_gate.py --preflight
```

- **产物**：完全兼容。G1 哈希基线一致（`build_single.py` 没改），G2 spec 一致。
- **断言**：新增 25 条会跑。若 payload 是旧版（缺 `liab_at_begin_total` 等），
  相关 4 条记 SKIP，不阻塞；其余照常。
- **结论**：升级后重跑一次门禁，若新增断言报 FAIL，**那是真问题，别当回归处理**。

### 2.0 的黄金基线要重设吗？

不要。`build_single.py` 未改，产物字节不变，基线继续有效。
只有当你**有意改版式**时才 `--rebless`（届时会先跑 G3）。

## 五、迁移步骤（已有项目）

```bash
# 1) 备份现有产线（注意：备份绝不能放 skills/ 下，会被当成同名技能重复登记）
xcopy /E /I "E:\<项目>\产线" "C:\Users\<你>\.workbuddy\skills-backup\<项目>_产线_bak"

# 2) 用 3.0 覆盖两个脚本
copy "<skills>\清算ABS项目汇报分析3.0\scripts\single\verify_single.py" "E:\<项目>\产线\scripts\single\"
copy "<skills>\清算ABS项目汇报分析3.0\scripts\single\repro_gate.py"    "E:\<项目>\产线\scripts\single\"

# 3) 体检
cd /d "E:\<项目>\产线\scripts\single"
python repro_gate.py --preflight

# 4) 跑门禁（不构建，用现有产物）
python repro_gate.py --html "E:\<项目>\03_报告产出\<产物>.html"

# 5) 若新增断言报 FAIL → 回查数据，不要 --rebless
```

## 六、3.0 新增的两个命令行开关

| 开关 | 作用 |
|---|---|
| `repro_gate.py --preflight` | 只做环境/输入/字段体检，不跑断言（秒级） |
| `verify_single.py --assets <dir>` | 指向任意单子的取数目录做复核，不必把数据塞进技能目录 |
| `verify_single.py --json <file>` | 导出结构化断言结果，便于批量统计 |
| `repro_gate.py --rebless --force --why "..."` | 强制跳过 G3 重设基线（须用户明确同意，原因写进 history.tsv） |

## 七、升级后必须重做的事

1. **所有已交付单全部重跑一遍门禁**（15 单实测累计回归 4 轮）。
   改了解析器或断言，单点通过不代表没有回归。
2. **把新增断言的 FAIL 当真实缺陷排查**，不要为了过而放宽容差。
   容差只在"确实是披露精度导致的舍入误差"时才调整，且要在注释里写清依据。
3. **记录基线变更**。任何 `--rebless` 都要在交付说明里写"为什么变"。
