## 6. 换成自己的项目（重要边界）

### 6.1 行数据

```bash
python -X utf8 scripts/aggregate_rows.py --projects-root "<项目根>" \
  --canonical assets/data/_rows_all.json --out dist/_rows_all.json
python -X utf8 scripts/aggregate_rows.py --check --rows dist/_rows_all.json
```

脚本只读每项目 `02_提取数据/{metrics,payload}.json` 和 `_assert_single.json`；
不解析 PDF，不替单项目补数。

### 6.2 基础壳

V9 的 **基础壳**（顶栏、区块骨架、`META`、`REPORTS`、`SLICE_ROWS`、项目卡、报告查看器）已经内嵌当前 74 单。
`V3_FULL` 只提供图表所需的完整字段；它不能单独变出一份新报告。

**换新项目时，必须同步重建基础壳的三块：**

| 块 | 用途 | 来源 |
|---|---|---|
| `META` | 项目元信息、KPI、筛选 | 行数据 + 项目目录 |
| `REPORTS` | 查看器正文 + 现金流/回购解析 | `03_报告产出/*.html` |
| `SLICE_ROWS` | 首屏项目带/明细行 | 行数据 + 报告 |

只换 `_rows_all.json` → 图表会变，但项目卡/报告查看器仍是旧 74 单，属于**假成功**，禁止交付。
基础壳的通用重建不在本包 1.0 的自动脚本内；本包提供 V9 参考壳、行契约和注入器。接新数据集时，按 `references/03` 的 DOM/数据契约改基础壳，再注入 V3。

### 6.3 如果只是复刻当前 74 单

不需要改基础壳；直接第 2–5 步即可，产物字节一致。

## 7. 交付

1. 输出 HTML + SHA256 + 字节数；
2. `_rows_all.json` + SHA256；
3. G0/G1/G2/G3 日志；
4. 版本号/日期/变更记录；
5. 数据限制（未入库字段、存续 4 单、小微剔除）。

## 8. 常见失败速查

| 现象 | 先查 |
|---|---|
| G0 DIFF | 解压损坏/有人改了源；重新解压 |
| G1 大小差几十字节 | 换行/编码/`newline`；不要手改产物 |
| G1 大段不同 | 用错 base/rows/source；检查 `--base/--rows` |
| G2 V3_FULL 非 74 | rows 文件错/空 |
| G2 行校验失败 | 字段/公式/日期/FAIL 单；见 06 |
| G3 0 charts | JS 错误/echarts 注入缺失 |
| G3 现金流解析 0 | `REPORTS` 缺报告或 `data-label` 丢失 |
| 现金流行点击无反应 | 基础壳的报告/项目键不匹配；见 03 |
| 图表数 12 | 现金流 HTML 板未渲染；查 `.cf-row` |
