# 19 · 取数契约与字段字典（v3）

> 这份文档回答一个问题：**要跑通 3.0 的门禁，payload / metrics 里必须有什么？**
> 缺哪个字段会让哪条断言失效、还是直接判失败，这里逐项标清楚。

## 一、为什么需要"契约"而不是"尽力而为"

2.0 的做法是：断言直接 `L["liab_at_begin_total"]` 取值。取数器没产出这个键时，脚本在
中途 `KeyError` 崩掉——**退出码 1，但没有任何断言日志**，使用者只看到一段 traceback，
无法区分「数据本身错」和「取数器漏项」。

3.0 把两件事分开：

| 情形 | 判定 | 退出码 | 提示 |
|---|---|---|---|
| 取数漏了必需字段 | **输入契约不满足** | **2** | 列出缺哪些键 + 怎么补 |
| 字段都在，但数值算不平 | **断言 FAIL** | **1** | 列出哪条断言 + 残差多少 |
| 字段都在，但该键对这份披露文件不适用 | **SKIP** | 0 | 明示"跳过，不代表通过" |

三种状态不能混。混了就会出现两种坏结果：要么漏项被当成通过，要么漏项被当成数据错。

## 二、必需字段（缺任一项 → EXIT=2，断言根本不跑）

### payload 顶层

`pool` · `tranche` · `liquidation` · `dist` · `periods` · `trust_account`

### payload.pool（资产池）

| 字段 | 含义 | 来源 | 缺失后果 |
|---|---|---|---|
| `balance_total` | 入池本息费合计 | 中债池统计表 | 几乎所有比例指标的分母，全崩 |
| `balance_principal` | 入池本金 | 中债池统计表 | 无法校验「本息费 = 本金 + 息费」 |
| `balance_interest_fee` | 入池利息费 | 中债池统计表 | 同上 |
| `exp_recovery_zz` | 中债预计回收金额 | 中债池统计表·预计回收总额 | 达成率、回采校验无基准 |
| `exp_rec_rate_zz` | 中债预计回收率 | 同上（**披露到 4 位小数**） | 回采校验无法进行 |
| `n_loans` | 入池笔数 | 中债池统计表 | 笔均、单笔分布无参照 |
| `n_borrowers` | 借款人数 | 同上 | 无法校验「人数 ≤ 笔数」 |

> ⚠ `exp_rec_rate_zz` 精度只有 4 位小数（如 `0.1828`）。用 40.87 亿 × 0.1828 反乘，
> 与披露的 7.4727 亿差 15.8 万是**数学必然**，不是数据错。回采校验的容差按
> `max(1e4, 入池 × 5e-5)` 设定，见 `20-跨单门禁清单v3.md` 第四节。

### payload.tranche（分档）

`senior`（含 `issue`）· `sub`（含 `issue`）· `total`

### payload.liquidation（清算，必需部分）

| 字段 | 含义 | 缺失后果 |
|---|---|---|
| `total_recovery` | 累计回收（本金 + 收入） | 回收率、处置费率、资金平衡全崩 |
| `account_interest` | 账户结息 | 资金平衡 |
| `fees_total` | 各项信托费用支出合计 | 费用率、资金平衡 |
| `fee_detail` | 费用明细 dict | 「处置费率」无来源 |
| `sen_principal_paid` / `sen_interest_paid` | 优先档本息兑付 | 资金平衡、分档校验 |
| `sub_principal_paid` / `sub_income_paid` | 次级档本息兑付 | 同上 |
| `residual_asset` | 剩余信托财产 | 恒等式② |
| `holder_equity_end` | 清算结束日持有人权益 | 恒等式①②、资金平衡 |

### fee_detail 核心科目

**`处置费`、`贷款服务费` 必须在场。** 理由：分配顺序以它们为前提，缺了整个"处置费率"
与"服务费率"都没有来源。缺 → EXIT=2（不是 FAIL）。

> 实测踩坑：OCR 会把科目名从中间断行（`受托\n机构报酬`），若匹配前不去空白，
> 该科目被静默丢弃，明细合计与披露差 25 万。3.0 用「明细合计 = 披露合计」这条
> 断言把它变成 FAIL；核心科目在场检查是第二道。

### payload.dist

`grade` · `occupation` · `region` 三个必须有（用于「分布余额合计 = 入池本息费」）。

### metrics

`securitization_rate` · `recovery_rate` · `dispose_fee_rate` · `achieve_rate` ·
`recovered` · `sen_xirr` · `sub_xirr` · `cum_at_period`

## 三、可选字段（缺 → 相关断言 SKIP，不计 FAIL）

这些字段来自较新的取数器。旧版 payload 没有，不影响核心结论。

> **4.0 的原则：所有「会改变数值」的新字段一律默认关闭（缺省＝老行为）。**
> 原因是 `build_single.py` / `verify_single.py` 是**跨行共用**代码，
> 任何无条件生效的新逻辑都会改到其他行已过 G1 字节基线的交付件。
> 实测教训：一项费用校准逻辑曾让惠元 G1 差 1 字节（审计费 49→47、差额 −580.45→−531.45），
> 加 `fee_calibrated` 开关后才隔离干净。

| 字段 | 用于 | 缺失后 |
|---|---|---|
| `liquidation.liab_at_begin_total` | 恒等式① | 恒等式①SKIP |
| `liquidation.liab_at_end_total` | 恒等式② | 恒等式②SKIP |
| `liquidation.cash_begin` | 恒等式① | 随①一起 SKIP |
| `liquidation.misc_fee` | 费用明细对平（未单列手续费） | 对平时按 0 处理，仍能查出漏项 |
| `liquidation.vat_included_in_fees` | 增值税口径 | 默认按"增值税单列"处理 |
| `liquidation.buyback.occurred` | 回购起算日检查 | 按"无回购"SKIP |
| `meta.first_pay_date` | 首付日 > 发行日 | SKIP |
| `meta.rf` | XNPV 折现率可见性 | SKIP |
| `meta.code_sub` | 次级档代码 7 位 | SKIP |
| `liquidation.recovery_includes_buyback` | **4.0 新增**。累计回收是否已含回购价款 | 缺 → 按旧公式「回收＋回购」相加（老单行为不变） |
| `liquidation.buyback.notice_date` / `calc_date` | **4.0**。回购通知书日 / 起算日 | 只有 occurred+price 时 SKIP，不判 FAIL |
| `dropped_annual[]` | **4.0**。被剔除的年度累计期次及其理由 | 缺 → 报告不写剔除脚注（不影响数值） |
| `metrics.sub_fixed_total` | **4.0**。次级档固定资金成本合计 | 缺 → 卡片不加「固资｜超额」拆分行、口径注解退回「不做倒算」 |
| `metrics.sub_excess_total` | **4.0**。次级档超额收益合计 | 同上 |
| `metrics.sub_reconcile_gap` | **4.0**。逐期次级收益合计与清算归属的负残差 | 缺 → 视为 0（不显示差额说明） |
| `metrics.flows` | **4.0 强化**。两档现金流（XIRR/XNPV 唯一输入） | 缺 → XIRR 复算断言 SKIP（但报告仍用硬编码兜底，**不可接受**，见反模式 3） |
| `fee_calibrated` | **4.0**。费用/利息是否被清算口径校准过（跨行隔离开关） | 缺 → 视为未校准（他行交付件行为不变） |

> **技能自带的第三期样例正是旧版 payload**，它有 4 项 SKIP（恒等式①②、首付日、rf）。
> 这是设计预期，不是缺陷。想要 137→138 全效，需用 3.0 取数器重出 payload。

## 四、字段字典（核心结构，按实际 payload 整理）

```

├─ meta             项目档案（33 项）
│   name / display_name / originator / trustee / servicer / custodian / underwriter
│   variety           信用卡不良 / 个人消费不良 …
│   cutoff_date       初始起算日
│   issue_date        发行日（信托财产交付日）
│   first_pay_date    首个支付日
│   terminate_date    信托终止日
│   liquidation_end   清算完毕日
│   legal_maturity    法定到期日
│   code_sen / code_sub   证券代码（7 位）
│   sm_pages          说明书页数
│   rf / rf_note      无风险利率与来源
│   file_name         产物文件名（repro_gate 用它推断 OUT_NAME）
│   missing_docs / missing_list   缺失材料

├─ pool             资产池（22 项）
│   n_loans / n_borrowers / contract_amount
│   balance_total / balance_principal / balance_interest_fee

│   senior {issue, coupon, share}  sub {...}  total
│   credit_enhance_pct（次级占比，**4 位小数**）  retention_pct

│   period / report / collect_start / collect_end / pay_date
│   begin_balance / end_balance / in_total / out_total / carry
│   outflow{科目: 金额}      ← 分配矩阵一行
│   sen_principal / sen_interest / sub_principal / sub_fixed_cost / sub_income
│   servicer_fee
│   sen_balance_after / sub_balance_after   ← 期末余额，必须单调不增且末期归零
│   liquidity_reserve
├─ liquidation      清算（35+ 项）
│   terminal_kind   A=有清算报告 / B=证券端终局但信托未终止

│   liab_at_begin_detail[] / liab_at_begin_total      ← 逐项解析，勿写死公式

│   terminate_date / liquidation_end
├─ dist             分布（10 维）

├─ forecast_flow[]  中债预测现金流
│   [收款期末, 期初, 回收, 期末]   ← 期初必须接上期期末；末期期末 = 0
```

## 五、metrics 关键字段

| 字段 | 口径 | 注意 |
|---|---|---|
| `securitization_rate` | 发行规模 ÷ 入池本息费 | |
| `recovery_rate` | 累计回收 ÷ 入池本息费 | |
| `dispose_fee_rate` | **处置费用 ÷ 累计回收** | 分母是回收，不是发行/入池 |
| `achieve_rate` | 实际累计回收 ÷ 中债预计回收 | **可能残留旧口径**，见下 |
| `sen_xirr` / `sub_xirr` | 全周期真实现金流 IRR | 3.0 增加合理区间断言 |
| `sen_xirr_gap_bp` | 优先档 XIRR − 票面（bp） | |
| `sub_multiple` | 次级档累计现金 ÷ 次级发行 | |
| `cum_at_period[]` | 逐期累计回收 | 用于累计一致性 |

> ⚠ **`achieve_rate` 可能残留旧口径**。第三期实测：`metrics.achieve_rate = 0.9115992`
> 是「18.28% × 入池」反推出来的旧值，与金额口径 `0.9114067` 差 **1.93bp**。
> 3.0 因此把它当"同源交叉检查"（容差 5bp），并要求**报告正文出现金额口径值**——
> 报告里呈现的必须是金额口径那一版。

## 七、铁律

**不要为了跑通门禁而在 payload 里手工填数。** 那等于让断言自证，门禁就废了。

字段缺失只有两条正路：
1. 回到取数脚本补齐，重出 payload / metrics；
2. 确认该字段对本单确实不适用（如无回购），改断言走 SKIP 分支。

绝不允许第 3 条：手工填一个"看起来对"的数。
