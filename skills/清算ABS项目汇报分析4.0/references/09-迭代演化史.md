## 二、逐轮要点

### v2（起点）
- 总览 28 卡重做（3 列 × 2 列信息布局）
- 项目档案面板重做（5 类归组：资产池情况→集中度与账龄→预期回收与发行结构→实际回收与处置→实际收益与期限）
- 横向对照重构、逐单稽核
- 折线图重绘 + 单位统一引擎
- **教训**：5 类顺序必须 `数组下标 == 分类序号 == 渲染顺序`，否则错位

### v3（做减法）
- 删除「成本强度」
- 次级档固定资金成本合并表
- 费用双渠道合并
- 处置费率分母唯一（÷ 累计回收）
- 折价率 → **证券化率**
- 02/03 改为回收款去向分布；中债预测 vs 实际强化；各档 XIRR 预测 vs 实际 + 超额收益
- **教训**：用户说「做减法」时，是**减内容不是减字号**

### v4（合并）
- 横向对照 + 逐单稽核合并为一页
- 4 个板块重做

### v5（大修）
- **折叠区独立成侧栏栏目「明细与底稿」**
- **P0：圆环图单位错标**（11.92 亿标成 11.92 万 → 差 10000 倍）
- 文案去技术化（payload/liq_info/alloc.cum 等字段路径全删）
- **信托终局性判据修正**：以信托计划终止为准，不是本金兑付
- 数据质量三段式重写（删内部编码 A_回源已补 等）
- 本地路径脱敏
- **教训**：「同图内单位词一致」的断言抓不到整图差 1 万倍 → 必须**跨图量级校验**

### v6（数据修正）
- **瀑布三重错**：
  - 优先档本金取成发行规模（7400 万 vs 5400 万）
  - 优先档利息取错（302 万 vs 59.34 万）
  - 处置费用重复计入（流出 10325 万 > 回收 8074 万）
- 单位校验扩到全图种（donut→hbar/treemap）
- ③④ 改 6/6 对称
- 集中度字段可得率治理（主体最高 39.3%、前5/10大 14.3% → 移入字段字典）
- 四舍五入统一 2 位
- ⑦⑧ 分工（⑦摘要 / ⑧明细）
- **教训**：`alloc.cum` 的「优先档本金」= 优先+次级总本金，证券受偿必须用 `alloc2`

### v7（版式）
- 兑付与清算时点并入 ⑤ 时间轴（7→9 节点）
- 资产池图 3+3+2+2
- 瀑布按金额降序 + 图例重叠修复
- 总览品种总结横排 + 关键指标 6 列
- 简单平均 → **算术平均**
- **教训**：`gridTemplateColumns` 返回 `repeat(6, minmax(0px,1fr))`，按空格切分会算错

### v8（筛选与恢复）
- 总览加**年份/银行/切片筛选器**（内容自动刷新，含点评与指标）
- 「22 单规模字段完整」移到发行合计右侧
- 品种总结移到虚线下方横排
- ① 资产池 2×2（户数/笔数合并一格用「/」）
- ② 集中度 2×2（加权平均逾期上移填灰格）
- ④ 处置费率 与 处置费用占比 **去重**
- **资产池 10 图按原图型恢复**（曾把全部圆环改成横条，用户纠正「我没说全部改」）
- **教训**：用户说「可以考虑 X」是**建议不是命令**；过度理解会返工

### v9（设计规格）
- 入池息费单位改亿元
- 10 图按设计规格书重构：
  - 帕累托×2（余额/预计回收率）
  - 100% 堆叠×2（五级/担保）
  - 垂直柱×4（逾期/年龄/年收入/授信）
  - Top8/Top10 水平条×2（职业 37 类 / 地区 342 类）
- 图型多样性 ≥4 种、圆环 0
- **教训**：口径/图型说明行必须放 SVG **外部**，否则旋转轴标签会压脚注

### v10（横向对照五板块）
- 01 四象限：X 改**处置费率**、气泡改**资产本金规模**
- 02 加 45° 对角线 + 比值分布
- 03 改「定价假设 vs 实际兑现」（原「预测 XIRR」是臆造字段）
- 04 瀑布 + 逐期堆叠 + 帕累托
- 05 定价思考
- **教训**：**「预测 XIRR」字段根本不存在** → 必须核实字段存在性再设计图表

### v11（取消倒算）
- **全面取消次级档固定资金成本倒算**（因口径有争议：期初 12.00% vs 期末 21.47%）
- 03 重构为 4 图：票面排序条+XIRR叠点 / 优先档偏差分布 / 次级档 XIRR 披露分布 / 超额收益 Top10+Bottom5
- 04 帕累托**只对费用类科目**（剔除证券本金/利息）
- 05 改为「各家实际各单 IRR 点评」
- ⑧ 加披露概览（逐单动态 N=a+b+c）+ 缺失材料真实表格（123 行）
- **教训**：**口径有争议的指标，宁可不做**，只展示披露值

## 三、用户偏好画像（做完再核对）

| 偏好 | 表现 |
|---|---|
| **做减法** | 「分清主次」；琐碎内容折叠；不要堆信息 |
| **口径要唯一** | 同一指标只能有一个分母；不一致必被发现 |
| **缺失要显性** | 「—」/「未披露」，绝不显示 0 或空 |
| **图表要有意义** | 反对「为了好看」的图型；反对全站同一种图 |
| **单位要统一** | 同区域不混亿/万；同图中心/图例/轴/tooltip 同源 |
| **文案要人话** | 不出现 `payload.xxx`、`liq_info`、`A_回源已补` 这类内部术语 |
| **每版重命名** | 不要覆盖旧版 |
| **交付要单一** | 不要零散文件，一个项目目录 |
| **多 agent + 稽核** | 明确要求 Lead 做总监、子智能体干活、Lead 稽核 |
| **不要臆造** | 缺字段就不画，推算值不当披露值 |

## 四、验证过的高效做法

1. **每轮先核实点评**（20% 是旧版信息）
2. **定量给证据**（截图 / DOM 输出 / 数值），不要只说"还是不对"
3. **断言先跑一次确认能抓住已知 bug**，再改实现
4. **保留清单**（修 A 破 B 是最常见回归）
5. **上一轮断言永不删除**（除非需求作废）
