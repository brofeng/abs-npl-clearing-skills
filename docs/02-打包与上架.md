# 打包与发布

## 一、两种发布物，别混

| 发布物 | 在哪 | 体积 | 用途 |
|---|---|---|---|
| 完整版技能 | `skills/<name>/` | 19 MB / 13 MB | GitHub 直接 clone，功能最全 |
| 市场上架包 | `market/*.zip` | 1.93 MB / 0.49 MB | 传 WorkBuddy 开放平台，硬上限 3 MB |

市场包不是「阉割版功能」，而是**去掉可再生的基线资产**：

| 技能 | 剔除 | 为什么必须剔 |
|---|---|---|
| 技能一 | `assets/golden/screens/`（≈8 MB 截图）、`assets/single/golden/`（≈1.7 MB） | PNG 几乎不可压缩，一个目录就顶满 3 MB |
| 技能二 | `assets/workbench/`（≈11.4 MB V9 成品） | 单文件 11 MB，压缩后仍远超上限 |

保留的：`SKILL.md`、`references/` 全部、`scripts/` 全部、`templates/`、契约、口径台账、示例 payload。
**方法与判据一个字不少**，缺的只是「拿来对比像素和字节的基准物」。

## 二、重新打包

```bash
# 只校验体积，不写盘
python -X utf8 tools/build_market_package.py --check

# 正式出包到 market/
python -X utf8 tools/build_market_package.py
```

脚本做的事：

1. 按 `EXCLUDE` 清单复制 `skills/<name>/` 到 `.stage/`；
2. 在包内生成 `references/99-完整资产包获取.md`（剔除清单 + 取回方式 + 缺失影响）；
3. 在 `SKILL.md` 末尾追加「市场版说明」小节，指向完整仓库；
4. 以 `defatelevel=9` 压缩为 `market/<zipname>.zip`，校验 ≤ 3 MB；
5. 清掉 `.stage/`。

## 三、发布前自检

```bash
python -X utf8 .github/scripts/validate_package.py
```

五项：技能结构、frontmatter 六字段、SemVer 三段式、全部 Python 可解析、
zip ≤ 3 MB 且 SKILL.md 在第一层、源码无本机用户名路径。

CI 会在每次 push / PR 时自动跑同一脚本。

## 四、版本号怎么升

- 只有 `SKILL.md` frontmatter 的 `version` 是权威版本；
- 改了口径、产物字节会变 → 至少升 minor（4.2.0 → 4.3.0）；
- 只改文档、错别字 → patch（4.2.0 → 4.2.1）；
- 同时更新 `CHANGELOG.md` 与 `market/` 里的 zip 文件名。

## 五、发 Release

```bash
git tag -a v4.2.0 -m "清算ABS项目汇报分析 4.2.0"
git push origin v4.2.0
```

GitHub Release 附件建议放：

- `abs-clearing-report-4.2.0.zip`（市场包）
- `abs-skill-01-full-assets.zip`（`assets/golden/screens` + `assets/single/golden` 的单独打包，
  供只想补基线的人下载，不必克隆整个仓库）
