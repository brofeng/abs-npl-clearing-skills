## 3. 常见故障

### G0/G1

- `G0 DIFF`：解压损坏或有人改源；重新解压，不要直接改 golden。
- `G1 大小差 1,483 B`：换行被转成 CRLF；检查写入 `newline`。
- `G1 大段不同`：用错 base/rows/source；检查 CLI 参数。
- `echarts` 注入报错：源里有 `</script>`；注入器已转义，不要手改。

### G2 行

- 行数 73：项目目录漏/名称不一致；`proj` 去空格匹配。
- 行数 67：用了旧 `_rows.json`（67 单）；切换 `_rows_all.json`。
- `achieve out of range`：实际可 101%/107%；允许 0–3。
- `sub_xirr/mult missing`：4 单存续允许 null，不要补。
- `recovery != recovered/pool`：单位/字段错；查源，不要放宽。
- `fails non-empty`：单项目 FAIL；回第一技能。

### G3 交互

- 0 charts：JS 错误；查 console；`__v3charts`。
- 现金流 0：`REPORTS` 缺/报告无 `data-label`；不要借邻单。
- 现金流行无反应：项目键/银行键不匹配；查 `data-bank/data-variety`。
- 银行页空白：基础壳没有该银行项目；检查 META/SLICE_ROWS。
- 查看器返回丢切片：查 `history`/`showView`；不要用 location 刷新。
- 双列在窄屏溢出：`@media(max-width:900px)` 单列；V9 有 off-canvas drawer 的 scrollWidth，不作门禁。

### 视觉

- 图表被裁：轴标题/图例/边距；V4/V9 已修，别回退。
- 卡片贴住：`grid2 + card` / `v3-pair + card` 间距 14px。
- 现金流板丑/高饱和：恢复 HTML 账本横条，不要 ECharts 渐变。
- s5 与现金流风格不一致：同一套墨蓝/香槟金/封包红 + 轨道。

## 4. 接新数据集边界

V9 的基础壳已带 74 单的 META/REPORTS/SLICE_ROWS。
新数据集必须同步重建这三块；只换 V3_FULL 会造成假成功。
本包 1.0 提供 V9 参考壳 + 行契约 + 注入器；基础壳的通用重建见包内说明/第一技能。
如果只是复刻当前 74 单，不需要动基础壳。

## 5. 交付失败升级

1. 保留现场：产物、日志、输入哈希、版本；
2. 按 G0→G1→G2→G3 定位，不要先改 UI；
3. 同一失败复现 2 次仍不过 → 停，写失败报告；
4. 不要用“截图看起来对”替代门禁。
