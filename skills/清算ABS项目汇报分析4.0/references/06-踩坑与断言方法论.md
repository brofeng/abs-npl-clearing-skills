# 06 · 踩坑与断言方法论

> 本项目 60+ 轮迭代、**22 次断言失败**中有约 **15 次是断言本身写错**。
> 这份文件是为了不再重犯。

## 一、断言方法论（核心）

### 原则
1. **渲染后文本才是真值**：客户端改写（去技术术语、改文案、重绘图表）后，源文件仍含原文 → 所有「改了没」的断言必须查 `document.title = 'VRESULT:'+JSON` 回传的渲染结果
2. **每条静态断言都要有对应的渲染断言**：静态只能证明「代码里写了」，不能证明「用户看到的是对的」
3. **断言应验证语义，不是验证字符串**：`"5,400" in labels` 会挂（显示是 `0.54 亿元`）；应写成比值/量级判断
4. **测试断言的断言**：新加的断言要先跑一次，**确认它能抓住已知 bug**，再去改实现

### 七类测量陷阱

| 陷阱 | 现象 | 正解 |
|---|---|---|
| **视口太窄** | 6 列变 3 列、3 列变 1 列 | `--window-size=1600,1400` 必须设 |
| **视图未激活** | `getBoundingClientRect()` 全 0 | 先 `click()` 激活再量 |
| **图表延迟渲染** | 没点进去过的视图还是原始态 | 图表转换在视图激活时触发 → 必须先激活 |
| **测量顺序** | 探针中途切视图，之前量的失效 | 「激活 → 量 → 再激活下一个」串行 |
| **opacity:0** | `innerText` 把未入场元素也算进去 | TreeWalker + computedStyle 判可见性 |
| **falsy 陷阱** | `(0 or 99) == 99` → 圆环 0 张被判失败 | `x if x is not None else 99` |
| **字符串比较顺序** | dict 遍历顺序不定 | 显式 `sorted()` 后再比 |

### 类名不要猜
先跑一次探针 dump 真实类名：
```js
var out=[]; document.querySelectorAll('#view-pX *').forEach(function(e){ if(e.className) out.push(String(e.className)); });
```
然后用真实类名写断言。

## 二、图表类踩坑

| # | 坑 | 描述 | 解法 |
|---|---|---|---|
| 1 | **单位整体错量级** | 圆环数值是「亿」量级却标「万」，**图内单位词完全自洽**（全标「万」） | 跨图/跨指标量级校验：合计必须在 [1000万, 1000亿] 或与 KPI 相对误差 ≤2 倍 |
| 2 | **只改单位词没改数值** | 把「万」改成「万元」，但数值 2.33 仍是亿量级 | 按真实总额**重算数值**，不是换标签 |
| 3 | **哑铃图退化** | 差异只有 −1~+4bp，哑铃线在 115bp 坐标轴上不可见 | 改「排序条 + 另一值叠点」 |
| 4 | **帕累托被本金主导** | 证券本金混入费用帕累托，累计线一柱到底 | **只对费用科目**做帕累托 |
| 5 | **旋转轴标签压脚注** | 让 SVG 高 46px 不够 | 把口径/图型说明行**移出 SVG 到 HTML 兄弟节点**（物理不可能重叠） |
| 6 | **标题串味** | 标题里残留「账龄面积」「棒棒糖」，与实际图型不符 | 标题只留图名，图型说明放脚注且必须与实际一致 |
| 7 | **卡片留大片空白** | 旧 viewBox 高（圆环用）套在新横条图上，内容只占下半 | viewBox 宽按**卡片实测内容宽**重算，高度=内容实高 |
| 8 | **图例被图形遮挡** | 图例叠在环/条上 | 图例独立成区（条上方或下方），SVG 内容区不含图例 |
| 9 | **圆环太多** | 37 类职业画圆环 → 完全看不清 | 类别 >15 必须 TopN 水平条 |
| 10 | **全改同一种图型** | 用户说「圆环过多可考虑横条」，被理解成「全部换掉」 | 按**原图型**逐张判断，只换真正看不清的 |

## 三、数据类踩坑

| # | 坑 | 解法 |
|---|---|---|
| 1 | `alloc.cum` 的「优先档本金」= 优先+次级总本金 | 证券受偿一律用 `alloc2` 的分档兑付表 |
| 2 | 处置费用重复计入（6 单） | 检测 `\|(rec − out_total) + 处置费用\| < max(1, rec×0.5%)`，命中则剔除并加注 |
| 3 | `subFixed` 28/28 有值但只有 8 单是真的 | 对比 `alloc2` 的 split 行与 `periods[].outflow` 逐期合计是否一致 |
| 4 | `xirr.sub.ref_rate` 是优先档票面不是次级约定率 | 看 `ref_rate_src` |
| 5 | 单利倒算用**期末**本金 → 率算高一倍 | 用**期初**本金（中誉至诚 12.00% 正确 vs 21.47% 错误） |
| 6 | `vsForecast` 3 单定义不一致 | 按定义 `recRate/expRecRate` 重算 |
| 7 | `pool_intfee` 缺入池利息（1 单） | 回源说明书核对，披露不静默 |
| 8 | 分配表 vs 逐期账户差 1–4.44%（7 单） | 瀑布「账面结余」如实显示，**不强行调平** |

## 四、组装/前端踩坑

| # | 坑 | 解法 |
|---|---|---|
| 1 | **模块 HTML 多一个 `</div>`** → 宿主 `.main` 提前闭合 → 后续视图掉到 `.app` 外、被挤到页面底部（表现为「空白视图」） | 组装器加**标签配平校验与自动修复** |
| 2 | `.main` 不是滚动容器 → `scrollTo(0,0)` 静默无效 | 注入 `toTop()`，清所有容器 scrollTop |
| 3 | CSS 注释里的 `{}` 破坏 `scope_css` 括号匹配 | 先剥离注释 |
| 4 | 选择器已含 root → 重复前缀失效 | 跳过，不加前缀 |
| 5 | `node --check` 只验语法不验引用 | 加运行时门禁（最小 DOM stub 跑一遍） |
| 6 | `subprocess.run` 没写 `encoding="utf-8"` → GBK 解码 → `stdout=None`（误报「无输出」） | 显式 `encoding="utf-8", errors="ignore"` |
| 7 | 内部函数被同名局部变量遮蔽 | 命名区分 `_has()` / `_res` |

## 五、跨 agent 环境坑

| 坑 | 现象 | 解法 |
|---|---|---|
| `%TEMP%` 里的 `.py` 遮蔽 stdlib | `import bisect` 失败，所有 agent 崩 | 检查 `%TEMP%` 有无同名 py，删掉 |
| 多人改同一文件 | 后写覆盖前写 | write scope 严格一个 owner |
| agent 自检的空断言 | 断言恒为 0 通过（形同虚设） | Lead 复核断言是否真能抓到问题 |

## 六、断言清单模板（每轮交付前）

```
静态（源文件）：
  [ ] 禁用词 0 次（折价率/预测XIRR/倒算率/已终局/内部编码/本地路径）
  [ ] 关键函数已注入
  [ ] 新模块已进入组装

渲染（无头浏览器）：
  [ ] 视图可切换、组件存在
  [ ] 数值口径正确（量级/单位/合计）
  [ ] 文字无截断且都有 tooltip
  [ ] 布局：等高、不溢出、不横向滚动、字号规范
  [ ] 折叠默认收起、筛选可用
  [ ] 无运行时错误（title 不以 ERR: 开头）

回归：
  [ ] 上一轮的断言全部仍 PASS
```

## 七、最后一条

**FAIL 不可怕，改断言让它通过才可怕。**
判断标准：这个断言如果 FAIL，**是否意味着用户会看到错误的东西**？
- 是 → 改实现
- 否 → 改断言（并用实测数据说明为什么不影响用户）
